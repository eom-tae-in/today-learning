> React 기반 블로그 토이프로젝트를 만들면서
> `Styled Components`, `json-server`, `Axios`, `useEffect`, `useParams`를 사용해
> 게시글 CRUD와 게시글-댓글 간 1:N 관계를 직접 구현했다.

---

## 오늘의 핵심 요약

- **데이터 흐름**: 사용자 이벤트가 API 요청으로 이어지고, 서버 응답을 React State에 반영한 뒤 UI가 다시 렌더링된다.
- **라우팅 흐름**: 상세 페이지는 `useParams()`로 URL의 게시글 ID를 읽고, 그 ID를 API 조회 조건으로 사용한다.
- **CRUD 패턴**: 생성은 `POST`, 조회는 `GET`, 수정은 `PATCH`, 삭제는 `DELETE`로 처리한다.
- **댓글 관계**: 댓글은 독립 데이터로 저장하되 `blogId`를 통해 부모 게시글과 연결한다.
- **State 갱신**: 추가는 spread, 수정은 `map()`, 삭제는 `filter()`를 사용해 새 배열을 만든다.

# 1. 전체 구조 이해하기

이번 토이프로젝트에서 가장 중요했던 것은 단순히 API를 호출하는 것이 아니라  
**URL → API → State → UI**가 어떻게 연결되는지 이해하는 것이었다.

```
사용자
  ↓
React Component
  ↓
Axios
  ↓
json-server
  ↓
db.json
```

게시글 상세 페이지에서는 URL의 `id`까지 함께 사용한다.

```
/posts/3
   ↓
useParams()
   ↓
id = 3
   ↓
GET /posts/3
   ↓
게시글 데이터
   ↓
setBlog(...)
   ↓
화면 렌더링
```

댓글은 게시글의 `id`를 기준으로 연결한다.

```
Post 3
 ├── Comment A
 ├── Comment B
 └── Comment C
```

즉, 댓글 데이터가 게시글 자체 안에 들어가는 것이 아니라  
댓글이 자신이 속한 게시글의 ID를 가지고 있는 방식이다.

# 2. Styled Components로 UI 구성

## Styled Components란?

Styled Components는 JavaScript 파일 안에서 CSS 스타일을 가진 컴포넌트를 만들 수 있게 해주는 라이브러리다.

```
npm install styled-components
```

기본적인 형태는 다음과 같다.

```
import styled from "styled-components";

const Wrapper = styled.div`
    padding: 16px;
    width: calc(100% - 32px);
    display: flex;
    flex-direction: column;
    align-items: center;
    justify-content: center;
`;
```

기존 HTML 태그처럼 사용할 수 있다.

```
const ExamplePage = () => {
    return (
        <Wrapper>
            <h1>Hello React</h1>
        </Wrapper>
    );
};
```

## 배운 점

Styled Components를 사용하면 스타일과 컴포넌트 구조를 같은 파일에서 관리할 수 있다.

특히 버튼처럼 여러 페이지에서 반복해서 사용하는 UI는 공통 컴포넌트로 분리하고, 필요한 경우 기존 컴포넌트를 다시 확장할 수 있다.

```
const LogoutButton = styled(Button)`
    background-color: #f44336;
    color: white;

    &:hover {
        background-color: #d32f2f;
    }
`;
```

# 3. json-server로 REST API 환경 만들기

백엔드 서버를 따로 구현하지 않고 CRUD 흐름을 연습하기 위해 `json-server`를 사용했다.

## 실행 명령어

```
npx json-server --watch db.json --port 5000
```

예를 들어 `db.json`을 다음처럼 구성할 수 있다.

```
{
  "blogs": [
    {
      "id": "1",
      "title": "React Study",
      "content": "React CRUD Practice",
      "category": "React"
    }
  ],
  "comments": [
    {
      "id": "1",
      "blogId": "1",
      "comment": "첫 번째 댓글"
    }
  ]
}
```

json-server는 이 데이터를 기준으로 REST API를 만들어준다.

|   |   |   |
|---|---|---|
|HTTP Method|API|역할|
|GET|`/blogs`|전체 게시글 조회|
|GET|`/blogs/1`|특정 게시글 조회|
|POST|`/blogs`|게시글 생성|
|PATCH|`/blogs/1`|게시글 일부 수정|
|DELETE|`/blogs/1`|게시글 삭제|
|GET|`/comments?blogId=1`|특정 게시글 댓글 조회|

# 4. Axios 인스턴스로 API 통신하기

매번 전체 주소를 작성하지 않기 위해 Axios 인스턴스를 만들어 사용했다.

```
import axios from "axios";

const api = axios.create({
    baseURL: "http://localhost:5000"
});

export default api;
```

이렇게 하면 다음처럼 작성할 수 있다.

```
api.get("/blogs");
```

실제 요청 주소는 다음과 같다.

```
http://localhost:5000/blogs
```

## 왜 Axios 인스턴스를 사용하는가?

API 서버 주소가 변경되더라도 모든 컴포넌트의 주소를 수정할 필요가 없다.

```
컴포넌트
   ↓
api.get("/blogs")
   ↓
Axios Instance
   ↓
http://localhost:5000/blogs
```

나중에는 여기에 인증 토큰 등을 넣는 interceptor도 추가할 수 있다.

# 5. useEffect로 게시글 목록 조회하기

메인 페이지가 처음 나타났을 때 게시글 목록을 불러오기 위해 `useEffect`를 사용했다.

```
import { useEffect, useState } from "react";
import api from "../../../api/axios";

const BlogMainPage = () => {
    const [blogs, setBlogs] = useState([]);

    useEffect(() => {
        api.get("/blogs")
            .then(response => {
                setBlogs(response.data);
            })
            .catch(err => {
                console.log("err", err);
            });
    }, []);

    return (
        <BlogList blogs={blogs} />
    );
};
```

## `[]`의 의미

```
useEffect(() => {
    // 실행할 코드
}, []);
```

의존성 배열이 비어있기 때문에 컴포넌트가 마운트된 뒤 한 번 실행된다.

정리하면 다음과 같다.

|   |   |
|---|---|
|작성 방식|실행 시점|
|`useEffect(fn)`|렌더링 후 매번|
|`useEffect(fn, [])`|최초 마운트 후 한 번|
|`useEffect(fn, [value])`|`value` 변경 시|

게시글 목록처럼 페이지 진입 시 한 번 데이터를 가져오는 작업에서 자주 사용된다.

# 6. 게시글 목록 렌더링

API로 받은 배열은 `map()`을 사용해 컴포넌트로 변환할 수 있다.

```
const BlogList = ({ blogs }) => {
    return (
        <>
            {blogs.map(blog => (
                <BlogItem
                    key={blog.id}
                    blog={blog}
                />
            ))}
        </>
    );
};
```

React에서 배열을 렌더링할 때 각 요소에는 고유한 `key`가 필요하다.

```
key={blog.id}
```

`key`를 통해 React가 각 요소를 구분하고 변경된 항목을 효율적으로 찾아낼 수 있다.

# 7. useParams로 URL의 게시글 ID 가져오기

게시글 상세 페이지에서는 어떤 게시글을 조회해야 하는지 알아야 한다.

라우터를 다음처럼 구성할 수 있다.

```
<Route
    path="/blog/read/:id"
    element={<BlogReadPage />}
/>
```

예를 들어 사용자가 아래 URL에 접근했다고 가정한다.

```
/blog/read/3
```

`useParams()`를 사용하면 `3`을 가져올 수 있다.

```
import { useParams } from "react-router-dom";

const BlogReadPage = () => {
    const { id } = useParams();

    console.log(id);
};
```

결과:

```
3
```

## 📌 핵심 구조

```
/blog/read/:id
          ↓
/blog/read/3
          ↓
useParams()
          ↓
{id: "3"}
```

`useParams()`가 반환하는 값은 객체이기 때문에 구조 분해 할당을 사용한다.

```
const { id } = useParams();
```

# 8. 특정 게시글 상세 조회

URL에서 가져온 ID를 API 요청에 사용한다.

```
const { id } = useParams();

const [blog, setBlog] = useState(null);

useEffect(() => {
    api.get(`/blogs/${id}`)
        .then(response => {
            setBlog(response.data);
        })
        .catch(err => {
            console.log("err", err);
        });
}, [id]);
```

흐름은 다음과 같다.

```
URL
 ↓
useParams()
 ↓
id
 ↓
GET /blogs/{id}
 ↓
response.data
 ↓
setBlog()
 ↓
화면 렌더링
```

# 9. 게시글 CRUD 전체 흐름

CRUD는 데이터 처리의 기본적인 네 가지 작업을 의미한다.

|   |   |   |
|---|---|---|
|CRUD|의미|HTTP Method|
|Create|생성|POST|
|Read|조회|GET|
|Update|수정|PATCH / PUT|
|Delete|삭제|DELETE|

---

# 10. Create - 게시글 작성

사용자가 입력한 값을 state에 저장하고 POST 요청으로 서버에 전달한다.

```
const [form, setForm] = useState({
    title: "",
    content: "",
    category: ""
});
```

입력값 변경:

```
<input
    type="text"
    value={form.title}
    onChange={e =>
        setForm(prev => ({
            ...prev,
            title: e.target.value
        }))
    }
/>
```

게시글 작성:

```
const createBlog = async () => {
    try {
        const response = await api.post("/blogs", form);

        if (response.status === 201) {
            console.log("게시글 작성 완료");
        }
    } catch (err) {
        console.log("err", err);
    }
};
```

## 📌 핵심

```
await api.post("/blogs", form);
```

두 번째 인자에 전달한 객체가 요청 body가 된다.

```
React State
   ↓
POST /blogs
   ↓
Request Body
   ↓
json-server
   ↓
db.json 저장
```

# 11. Read - 게시글 조회

전체 목록 조회:

```
const response = await api.get("/blogs");

setBlogs(response.data);
```

특정 게시글 조회:

```
const response = await api.get(`/blogs/${id}`);

setBlog(response.data);
```

조회한 데이터는 화면에 반영하기 위해 state에 저장한다.

```
API Response
    ↓
response.data
    ↓
setBlogs()
    ↓
State 변경
    ↓
React 재렌더링
```

# 12. Update - 게시글 수정

게시글 일부 데이터만 변경할 때는 `PATCH`를 사용할 수 있다.

```
const updateBlog = async () => {
    try {
        const response = await api.patch(`/blogs/${id}`, {
            title,
            content,
            category
        });

        console.log("수정 완료");
        console.log(response.data);
    } catch (err) {
        console.log("err", err);
    }
};
```

## 📌 PATCH와 PUT

|   |   |
|---|---|
|Method|의미|
|PATCH|데이터 일부 수정|
|PUT|전체 데이터를 새 값으로 교체|

이번 실습에서는 필요한 값만 수정하기 위해 `PATCH`를 사용했다.

api.delete(`/blogs/${id}`);

# 14. CRUD를 React 관점에서 이해하기

CRUD 자체보다 더 중요한 것은 **API 결과와 React State를 어떻게 동기화하는가**였다.

```
Create
POST 요청
   ↓

   ↓

Read
GET 요청
   ↓

Update
PATCH 요청
   ↓

   ↓

Delete

   ↓
기존 배열에서 해당 데이터 제거
```

# 15. 게시글과 댓글의 1:N 관계

이번 실습에서 게시글 하나에는 댓글이 여러 개 존재할 수 있다.

이것을 **일대다(1:N) 관계**라고 볼 수 있다.

```
Blog
 │
 ├── Comment
 ├── Comment
 ├── Comment
 └── Comment
```

즉,

```
게시글 1 : 댓글 N
```

관계다.

예를 들어 `db.json`에서 다음처럼 표현할 수 있다.

```
{
  "blogs": [
    {
      "id": "1",
      "title": "React CRUD"
    }
  ],
  "comments": [
    {
      "id": "1",
      "blogId": "1",
      "comment": "첫 번째 댓글"
    },
    {
      "id": "2",
      "blogId": "1",
      "comment": "두 번째 댓글"
    }
  ]
}
```

두 댓글 모두 다음 값을 가진다.

```
"blogId": "1"
```

따라서 둘 다 `id = 1`인 게시글에 속한 댓글이다.

# 16. 특정 게시글의 댓글 조회하기

json-server에서는 Query Parameter를 이용해 특정 게시글의 댓글만 조회할 수 있다.

```
api.get(`/comments?blogId=${id}`);
```

예를 들어 `id`가 `3`이라면 실제 요청은 다음과 같다.

```
GET /comments?blogId=3
```

댓글 조회 코드는 다음처럼 작성할 수 있다.

```
const [comments, setComments] = useState([]);

const getComments = async () => {
    try {
        const response = await api.get(
            `/comments?blogId=${id}`
        );

        setComments(response.data);
    } catch (err) {
        console.log("err", err);
    }
};
```

상세 페이지 진입 시 게시글과 댓글을 함께 조회할 수도 있다.

```
useEffect(() => {
    getBlog();
    getComments();
}, [id]);
```

# 17. 댓글 생성

댓글을 만들 때 중요한 것은 **어떤 게시글의 댓글인지 함께 저장하는 것**이다.

```
const [newComment, setNewComment] = useState("");
```

댓글 등록:

```
const createComment = async () => {
    try {
        const response = await api.post("/comments", {
            blogId: id,
            comment: newComment
        });

        console.log("댓글 작성 완료");
        console.log(response.data);
    } catch (err) {
        console.log("err", err);
    }
};
```

핵심 데이터:

```
{
    blogId: id,
    comment: newComment
}
```

`blogId`가 있어야 이 댓글이 어떤 게시글에 속하는지 알 수 있다.

# 18. 댓글 추가 후 화면 즉시 업데이트

댓글을 작성한 뒤 매번 전체 댓글을 다시 조회할 수도 있지만, 서버가 반환한 새 댓글을 기존 state에 바로 추가할 수도 있다.

```
setComments(prev => [
    ...prev,
    response.data
]);
```

기존 배열:

```
[A, B, C]
```

새 댓글:

```
D
```

결과:

```
[A, B, C, D]
```

React에서는 state 배열을 직접 수정하지 않고 새로운 배열을 만들어 전달하는 것이 중요하다.

잘못된 방식:

```
comments.push(response.data);
```

권장 방식:

```
setComments(prev => [
    ...prev,
    response.data
]);
```

# 19. 댓글 수정

오늘 구현하면서 특히 중요했던 부분 중 하나가 댓글 수정 후 React State를 갱신하는 방법이었다.

```
const patchComment = async ({ commentId, newComment }) => {
    try {
        const response = await api.patch(
            `/comments/${commentId}`,
            {
                comment: newComment
            }
        );

        if (response.status === 200) {
            setComments(arr =>
                arr.map(comment =>
                    comment.id === commentId
                        ? response.data
                        : comment
                )
            );
        }
    } catch (err) {
        console.log("err", err);
    }
};
```

## 📌 핵심 로직

```
setComments(arr =>
    arr.map(comment =>
        comment.id === commentId
            ? response.data
            : comment
    )
);
```

기존 댓글 배열을 순회하면서 수정할 댓글만 서버에서 받은 새로운 객체로 바꾼다.

```
기존
[
 A,
 B,
 C
]

B 수정

결과
[
 A,
 B',
 C
]
```

## 💡 왜 `map()`을 사용하는가?

React State는 직접 수정하지 않는 것이 기본 원칙이다.

따라서 기존 객체를 직접 변경하는 대신 새로운 배열을 만들어 `setComments()`에 전달한다.

# 20. 댓글 삭제

댓글 삭제 역시 ID를 이용한다.

```
const deleteComment = async (commentId) => {
    try {
        const response = await api.delete(
            `/comments/${commentId}`
        );

        if (response.status === 200) {
            setComments(prev =>
                prev.filter(
                    comment => comment.id !== commentId
                )
            );
        }
    } catch (err) {
        console.log("err", err);
    }
};
```

## 📌 핵심

삭제할 댓글만 배열에서 제외한다.

```
prev.filter(
    comment => comment.id !== commentId
)
```

예를 들어:

```
[A, B, C]
```

`B`를 삭제하면:

```
[A, C]
```

# 21. 댓글 CRUD와 배열 메서드 연결하기

댓글 CRUD를 구현하면서 React State와 배열 메서드가 자연스럽게 연결됐다.

|   |   |   |
|---|---|---|
|작업|HTTP|State 처리|
|댓글 생성|POST|spread `...`|
|댓글 조회|GET|`setComments()`|
|댓글 수정|PATCH|`map()`|
|댓글 삭제|DELETE|`filter()`|

```

Update  → prev.map(...)

Delete  → prev.filter(...)
```

# 22. 오늘 발생했던 `undefined` 문제

댓글 수정 과정에서 다음과 같은 요청이 발생했다.

```
PATCH http://localhost:5000/comments/undefined
```

이 경우 문제는 Axios 자체가 아니라 `commentId`가 함수에 제대로 전달되지 않았기 때문이다.

함수가 다음처럼 정의되어 있다면:

```
const patchComment = async ({
    commentId,
    newComment
}) => {
    // ...
};
```

이 함수는 **하나의 객체를 인자로 받는다.**

따라서 호출도 객체 형태로 해야 한다.

```
patchComment({
    commentId: comment.id,
    newComment: editComment
});
```

반대로 이렇게 호출하면:

```
patchComment(
    comment.id,
    editComment
);
```

함수의 매개변수 구조와 맞지 않는다.

# 23. `{}`와 일반 매개변수의 차이

다음 두 함수는 의미가 다르다.

## 일반 매개변수

```
const updateComment = (
    commentId,
    newComment
) => {
};
```

호출:

```
updateComment(
    comment.id,
    editComment
);
```

---

## 객체 구조 분해

```
const updateComment = ({
    commentId,
    newComment
}) => {
};
```

호출:

```
updateComment({
    commentId: comment.id,
    newComment: editComment
});
```

즉,

```
({ commentId, newComment })
```

는 단순히 변수를 두 개 받는 것이 아니라  
**전달받은 객체에서** `**commentId**`**와** `**newComment**` **속성을 꺼내겠다는 뜻**이다.

---

# 24. `setComments(...map())`에서 return이 필요 없는 이유

오늘 작성했던 코드:

```
setComments(arr =>
    arr.map(comment =>
        comment.id === commentId
            ? response.data
            : comment
    )
);
```

여기서는 별도의 `return`이 필요하지 않다.

화살표 함수에서 `{}`를 사용하지 않고 바로 표현식을 작성하면 그 결과가 자동으로 반환되기 때문이다.

```
comment =>
    comment.id === commentId
        ? response.data
        : comment
```

위 코드는 다음 코드와 같다.

```
comment => {
    return comment.id === commentId
        ? response.data
        : comment;
}
```

하지만 `{}`를 직접 사용하면 `return`을 작성해야 한다.

```
arr.map(comment => {
    return comment.id === commentId
        ? response.data
        : comment;
});
```

# 29. 컴포넌트 Mount와 useEffect

# 오늘의 정리

오늘은 React에서 단순히 화면을 만드는 것을 넘어  
**실제 데이터가 생성되고, 조회되고, 수정되고, 삭제된 뒤 화면에 다시 반영되는 전체 흐름**을 구현했다.

특히 CRUD를 구현하면서 다음 흐름이 가장 중요했다.

```
사용자 이벤트
    ↓
API 요청
    ↓
서버 데이터 변경
    ↓
response
    ↓
React State 변경
    ↓
재렌더링
```

또한 게시글과 댓글을 구현하면서 1:N 관계를 프론트엔드에서 어떻게 다루는지도 확인했다.

댓글은 단순한 독립 데이터가 아니라:

```
blogId: id
```

처럼 부모 게시글을 식별하는 값을 가지고 있어야 했다.

결국 오늘 구현한 구조를 한 문장으로 정리하면:

> **React CRUD는 HTTP 요청 자체보다 서버 데이터와 React State를 어떻게 동기화할 것인지 이해하는 것이 핵심이다.**

---

# 추가로 이해하게 된 점

- `useEffect`는 단순히 "처음 실행하는 함수"가 아니라 렌더링 이후 side effect를 처리하는 Hook이다.
    
- `useParams`를 사용하면 URL 자체를 데이터 조회 조건으로 활용할 수 있다.
    
- CRUD의 HTTP Method와 React 배열 처리 방법을 연결해서 생각하면 구현이 쉬워진다.
    
- `map()`은 수정, `filter()`는 삭제, spread는 추가 작업에서 자주 사용된다.
    
- 댓글과 같은 하위 데이터는 부모 데이터의 ID를 가지고 관계를 표현할 수 있다.
    
- API 요청 성공 이후 화면까지 변경하려면 결국 State를 갱신해야 한다.
    
- 함수의 매개변수를 객체 구조 분해로 받는 경우 호출부에서도 객체 형태를 맞춰 전달해야 한다.
    
- `undefined`가 API URL에 들어간다면 서버보다 먼저 함수 호출부와 ID 전달 과정을 확인해야 한다.
