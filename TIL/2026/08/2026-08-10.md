# 1. React Re-rendering

## Re-rendering이란?

React 컴포넌트가 이미 화면에 표시된 이후  
**State 등의 변화로 컴포넌트 함수가 다시 실행되고 화면이 갱신되는 과정**이다.

예를 들어 날씨 데이터를 State로 관리한다고 하면:

```jsx
const [weather, setWeather] = useState(null);
```

API에서 새로운 데이터를 받은 뒤:

```jsx
setWeather(data);
```

State가 변경된다.

전체 흐름은 다음과 같다.

```text
API Response
     ↓
setWeather(data)
     ↓
weather State 변경
     ↓
Component Re-rendering
     ↓
변경된 데이터를 화면에 표시
```

### 핵심

```text
State 변경
   ↓
Re-rendering
   ↓
UI 갱신
```

React에서는 DOM을 직접 찾아서 수정하기보다  
**State를 변경하면 React가 변경된 상태를 기준으로 UI를 다시 구성한다.**

---

# 2. Mount와 Re-rendering의 차이

오늘 다시 구분해야 했던 개념이 **Mount와 Re-rendering**이다.

|구분|의미|
|---|---|
|Mount|컴포넌트가 화면에 처음 등장|
|Re-rendering|State 등의 변경으로 컴포넌트가 다시 렌더링|
|Unmount|컴포넌트가 화면에서 제거|

흐름으로 보면 다음과 같다.

```text
Component 생성
      ↓
Render
      ↓
DOM 반영
      ↓
Mount
      ↓
useEffect 실행
```

이후 State가 변경되면:

```text
setState()
    ↓
State 변경
    ↓
Re-rendering
```

여기서 중요한 점은 **Re-rendering이 발생했다고 Mount가 다시 발생하는 것은 아니라는 것**이다.

---

# 3. `useEffect`와 외부 API

지도 초기화나 API 요청은 렌더링 과정 자체가 아니라  
렌더링 이후 실행해야 하는 **Side Effect**에 해당한다.

```jsx
useEffect(() => {

    // 지도 초기화
    // 현재 위치 조회
    // API 요청

}, []);
```

빈 의존성 배열을 사용하면:

```jsx
useEffect(() => {
    // ...
}, []);
```

컴포넌트가 처음 Mount된 이후 한 번 실행된다.

|작성 방식|실행 시점|
|---|---|
|`useEffect(fn)`|렌더링 이후 매번|
|`useEffect(fn, [])`|최초 Mount 이후|
|`useEffect(fn, [value])`|`value` 변경 이후|

따라서 오늘처럼 **페이지에 처음 진입했을 때 지도와 현재 위치를 초기화하는 작업**에 사용할 수 있다.

# 4. Open API란?

Open API는 외부 서비스가 제공하는 데이터나 기능을  
다른 애플리케이션에서 사용할 수 있도록 공개한 API이다.

오늘 사용한 기능을 기준으로 정리하면:

|기능|역할|
|---|---|
|Browser Geolocation|현재 위치 조회|
|Kakao Map API|지도와 Marker 표시|
|Weather API|현재 위치의 날씨 조회|

기본적인 Open API 사용 흐름은 대부분 비슷하다.

```text
React
  ↓
HTTP Request
  ↓
External API Server
  ↓
HTTP Response
  ↓
JSON Data
  ↓
React State
  ↓
UI
```

즉 특정 API의 사용법을 전부 외우기보다  
**Request → Response → State → UI** 구조를 이해하는 것이 중요하다.

# 5. Open API 사용 전 설정

Open API는 코드를 작성하기 전에 먼저 서비스에서 사용할 수 있도록 설정해야 한다.

Kakao Map API에서는 다음 과정을 진행했다.

```text
Kakao Developers
      ↓
애플리케이션 생성
      ↓
JavaScript Key 확인
      ↓
Web 플랫폼 등록
      ↓
사이트 도메인 등록
      ↓
Kakao Map API 사용
```

오늘 확인한 핵심 설정은 다음과 같다.

|설정|역할|
|---|---|
|애플리케이션|API를 사용할 프로젝트 등록|
|JavaScript Key|JavaScript SDK에서 사용할 앱 키|
|Web 플랫폼|API를 사용할 웹 환경 등록|
|사이트 도메인|API 요청을 허용할 웹 주소 등록|

### 배운 점

API Key를 발급받았다고 바로 API를 사용할 수 있는 것은 아니다.

서비스에 따라:

```text
API Key
+ 플랫폼 설정
+ 도메인 설정
+ API 활성화
```

등의 추가 설정이 필요할 수 있다.

# 6. Kakao Maps SDK 확인

React 코드에서 Kakao Map을 사용하기 전에  
SDK가 정상적으로 로드되었는지 확인했다.

```jsx
if (!window.kakao || !window.kakao.maps) {
    console.log("Kakao Maps SDK가 로드되지 않았습니다.");
    return;

window.kakao.maps.load(() => {
    // 지도 생성
});
```

지도 관련 코드를 실행할 수 있다.

### 핵심 흐름

```text
Kakao SDK Script
       ↓
window.kakao
       ↓
window.kakao.maps
       ↓
maps.load()
       ↓
지도 생성
```

외부 JavaScript SDK를 사용할 때는  
**SDK가 실제로 로드된 이후 관련 객체를 사용해야 한다.**

# 8. 위치 데이터가 API를 연결하는 기준이 된다

오늘 실습에서 `lat`, `lon`은 단순한 위치 값이 아니었다.

하나의 위치 데이터를 서로 다른 API에서 공통으로 사용할 수 있었다.

```text
navigator.geolocation
          ↓
    latitude / longitude
          ↓
     ┌────┴────┐
     ↓         ↓
Kakao Map   Weather API
```

즉:

```text
현재 위치
   ↓

   ↓
 ┌─┴──────────────┐
 ↓                ↓
지도 위치       날씨 조회
```

**한 기능에서 얻은 데이터를 다른 기능의 입력값으로 연결하는 구조**를 직접 확인했다.

# 9. Kakao Map 생성

Kakao Map에서는 먼저 지도를 표시할 HTML 요소가 필요하다.

```jsx
const container = document.getElementById("map");
```

지도 중심 위치는 `LatLng` 객체로 만든다.

```jsx
const centerPosition =
    new window.kakao.maps.LatLng(lat, lon);
```

그리고 해당 위치를 기준으로 Map을 생성한다.

```jsx
const map = new window.kakao.maps.Map(container, {
    center: centerPosition,
    level: 3
});
```

구조는 다음과 같다.

```text
latitude + longitude
        ↓
kakao.maps.LatLng
        ↓
centerPosition
        ↓
kakao.maps.Map
```

# 10. Kakao Map Marker 표시

지도 위에 현재 위치를 표시하기 위해 Marker를 생성했다.

```jsx
const marker = new window.kakao.maps.Marker({
    position: centerPosition
});
```

Marker를 생성한 것만으로는 지도에 나타나지 않는다.

```jsx
marker.setMap(map);
```

을 통해 어느 지도에 표시할 것인지 지정해야 한다.

전체 흐름:

```text
lat / lon
   ↓
LatLng
   ↓
position
   ↓
Marker 생성
   ↓
marker.setMap(map)
   ↓
지도에 Marker 표시
```

# 11. 지도와 Marker 관계

오늘 작성한 지도 관련 핵심 코드를 묶으면 다음과 같다.

```jsx
const position =
    new window.kakao.maps.LatLng(lat, lon);

const map =
    new window.kakao.maps.Map(container, {
        center: position,
        level: 3
    });

const marker =
    new window.kakao.maps.Marker({
        position: position
    });

marker.setMap(map);
```

각 객체의 역할을 정리하면:

|객체|역할|
|---|---|
|`LatLng`|위도·경도를 Kakao Map에서 사용할 위치 객체로 변환|
|`Map`|실제 지도 생성|
|`Marker`|지도 위 특정 위치 표시|
|`setMap()`|Marker를 특정 Map에 연결|

결국 Kakao Map의 핵심 구조는:

```text
LatLng
 ├── Map.center
 │
 └── Marker.position
```

처럼 이해할 수 있다.

# 12. `fetch()`를 이용한 HTTP 요청

Weather API 데이터를 가져오기 위해 `fetch()`를 사용할 수 있다.

기본적인 형태는 다음과 같다.

```jsx
const response = await fetch(url);
const data = await response.json();
```

`fetch()`의 흐름을 나누면:

```text
fetch(url)
    ↓
HTTP Request
    ↓
API Server
    ↓
HTTP Response
    ↓
response
    ↓
response.json()
    ↓
JavaScript Object
```

여기서 중요한 것은 `response`와 실제 JSON 데이터가 다르다는 점이다.

```jsx
const response = await fetch(url);
```

여기까지는 HTTP 응답 객체이다.

실제 JSON 데이터를 사용하려면:

```jsx
const data = await response.json();
```

으로 변환한다.

# 14. API 데이터의 단위 확인

외부 API를 사용할 때는 **값뿐만 아니라 단위도 확인해야 한다.**

예를 들어 날씨 API에서:

```json
{
    "temp": 300
}
```

이라는 데이터가 왔다고 해서 무조건 `300°C`를 의미하는 것은 아니다.

API마다 기본 단위가 다를 수 있기 때문이다.

따라서 데이터를 사용할 때는:

```text
API Response 확인
        ↓
필드 의미 확인
        ↓
단위 확인
        ↓
필요하면 변환
        ↓
화면 표시
```

순서로 확인해야 한다.

### 핵심

> API의 JSON 구조만 보는 것이 아니라 공식 문서에서 **필드의 의미와 단위**까지 함께 확인해야 한다.

# 15. API 요청과 React State 연결

오늘 학습한 핵심 코드 패턴을 가장 단순하게 만들면 다음과 같다.

```jsx
const [data, setData] = useState(null);

const getData = async () => {

    const response = await fetch(url);
    const result = await response.json();

    setData(result);
};
```

이 코드에서 각각의 역할은 다음과 같다.

|코드|역할|
|---|---|
|`fetch(url)`|API 요청|
|`response`|HTTP 응답|
|`response.json()`|JSON 데이터 변환|
|`result`|실제 JavaScript 데이터|
|`setData(result)`|State 갱신|
|Re-rendering|변경된 State를 UI에 반영|

따라서 다음 관계를 기억하면 된다.

```text
API
 ↓
Response
 ↓
JSON
 ↓
State
 ↓
UI
```

# 18. 문제가 발생했을 때 확인할 순서

API가 정상적으로 동작하지 않을 때는 무작정 코드를 수정하기보다 단계별로 확인한다.

|순서|확인할 내용|
|---|---|
|1|Console에 JavaScript 오류가 있는가?|
|2|Network에서 요청이 실제로 발생했는가?|
|3|요청 URL이 올바른가?|
|4|HTTP Status는 정상인가?|
|5|Response 데이터가 정상인가?|
|6|API Key가 올바른가?|
|7|플랫폼 / 도메인 설정이 되어 있는가?|
|8|필요한 값이 State까지 전달되는가?|

특히 SDK를 사용하는 경우 Network 탭에는 내가 직접 요청한 데이터뿐 아니라  
**SDK 내부에서 사용하는 이미지나 기타 리소스 요청도 나타날 수 있다.**

따라서 처음 보는 요청이 있다고 해서 바로 오류라고 판단하지 않는다.

## 현재 위치

navigator.geolocation.getCurrentPosition((position) => {

    const lat = position.coords.latitude;

const map =
    new window.kakao.maps.Map(container, {

const response = await fetch(url);
const data = await response.json();

setWeather(data);

## ✅ 잘한 점

### 📝 상황

React에서 외부 API를 사용하는 방법을 학습하면서 Kakao Map과 Weather API를 실제 프로젝트에 연결했다.

### 🚀 액션

API Key 발급부터 플랫폼 설정, SDK 로드, 현재 위치 조회, 지도 생성, Marker 표시, 날씨 API 요청까지 직접 연결했다.

특히 단순히 예제 코드를 실행하는 데서 끝내지 않고 문제가 발생했을 때 Console과 Network를 확인하면서 **어느 단계에서 문제가 발생했는지 추적하려고 했다.**

### 👏 칭찬

Kakao Map과 Weather API를 별개의 기능으로만 보지 않고:

```text
현재 위치
   ↓
lat / lon
   ↓
Map + Weather
```

처럼 **공통 데이터인 좌표를 중심으로 기능을 연결한 점**이 좋았다.

## 🔧 개선점

### ❗ 문제

Kakao Map API를 처음 설정하면서 JavaScript Key, Web 플랫폼, 도메인 등록, API 사용 설정처럼 코드 외부에서 필요한 과정이 많아 흐름이 다소 헷갈렸다.

또한 Network에 나타나는 SDK 내부 리소스 요청이나 위치 정보에서 반환되는 지역명을 보면서 어떤 요청이 직접 작성한 요청인지 구분하기 어려운 부분이 있었다.

### 🔍 원인

Open API를 처음 사용할 때 코드에만 집중하면:

```text
서비스 설정
→ SDK 로드
→ Browser API
→ HTTP 요청
→ Response
→ React State
```

중 어느 단계에서 문제가 발생했는지 구분하기 어렵다.

### 🎯 액션 플랜

앞으로 API 연동 문제가 발생하면:

```text
API 설정
   ↓
SDK 로드 여부
   ↓
Console
   ↓
Network Request
   ↓
Status Code
   ↓
Response
   ↓
State
   ↓
UI
```

순서로 문제를 추적한다.

## 📚 배운 점

### 💡 배움

오늘 가장 중요하게 이해한 것은 **Open API와 React가 연결되는 전체 데이터 흐름**이다.

단순히:

```jsx
fetch(url);
```

을 사용하는 것이 API 연동의 전부가 아니다.

실제로는:

```text
외부 데이터 획득
      ↓
JavaScript에서 처리
      ↓
React State에 저장
      ↓
State 변경
      ↓
Re-rendering
      ↓
UI 반영
```

까지 이어져야 하나의 기능이 완성된다.

또한 여러 API를 함께 사용할 때는 **서로 연결할 수 있는 공통 데이터가 무엇인지 찾는 것이 중요하다.**

오늘 실습에서는:

```text
latitude + longitude
```

가 Kakao Map과 Weather API를 연결하는 공통 데이터였다.

### 🌱 의미

이전에는 API 요청을 단순히 **"서버에서 데이터를 가져오는 코드"** 정도로 생각했다면, 오늘은 React 애플리케이션 전체 관점에서:

> **사용자/브라우저 → 데이터 → API → State → Re-rendering → UI**

로 이어지는 구조를 이해할 수 있었다.

앞으로 다른 Open API를 사용하더라도 API마다 문법을 처음부터 외우기보다:

```text
어떤 요청을 보내는가?
        ↓
어떤 데이터를 받는가?
        ↓
어떤 데이터가 필요한가?
        ↓
어떤 State에 저장하는가?
        ↓
화면에서 어떻게 사용하는가?
```

를 먼저 생각하면 훨씬 구조적으로 접근할 수 있을 것 같다.
