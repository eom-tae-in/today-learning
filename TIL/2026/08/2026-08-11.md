# 📚 학습 내용

## 1. Java 개발 환경

### 개념

Java 개발을 위해서는 **JDK(Java Development Kit)**가 필요하다.

- **JDK** : Java 프로그램을 개발하고 실행하기 위한 도구 모음
    
- **OpenJDK** : 오픈소스로 제공되는 Java SE 구현체
    
- **Temurin JDK** : Eclipse Adoptium에서 OpenJDK를 빌드하여 배포하는 JDK

즉, Temurin은 별도의 Java 언어가 아니라 **OpenJDK 기반의 JDK 배포판**이다.

### 동작 흐름

```text
Main.java
   ↓ javac
컴파일
   ↓
Main.class
   ↓ java
JVM에서 실행
```

Java 소스 코드는 먼저 바이트코드(`.class`)로 컴파일되고, JVM이 이를 실행한다.

### 핵심 코드

```java
public class Main {

    public static void main(String[] args) {
        System.out.println("Hello Java");
    }

}
```

### 핵심 포인트

> Java 클래스는 모두 컴파일할 수 있지만, `main()` 메서드가 있는 클래스가 프로그램의 실행 시작점이 되며 JVM이 해당 바이트코드를 실행한다.

## 2. 변수 타입과 타입 캐스팅

### 개념

Java의 타입은 크게 **기본 타입(Primitive Type)**과 **참조 타입(Reference Type)**으로 나뉜다.

|구분|예시|특징|
|---|---|---|
|기본 타입|`int`, `long`, `double`, `boolean`, `char`|값 자체를 다룸|
|참조 타입|`String`, 배열, 클래스|객체를 참조하는 값을 다룸|

타입이 다른 값끼리 대입할 때는 상황에 따라 타입 변환이 필요하다.

### 동작 흐름

```text
작은 타입 → 큰 타입
자동 형변환

큰 타입 → 작은 타입
명시적 형변환 필요
```

### 핵심 코드

```java
int number = 10;
double value = number;      // 자동 형변환

double pi = 3.14;
int result = (int) pi;      // 명시적 형변환
```

### 핵심 포인트

> 작은 범위의 타입을 큰 범위로 변환하는 것은 자동으로 가능하지만, 반대 방향은 데이터 손실 가능성이 있어 명시적인 캐스팅이 필요하다.

---

## 3. 메서드와 패키지

### 개념

**메서드(Method)**는 특정 기능을 수행하는 코드의 묶음이다.

```text
접근제어자 반환타입 메서드명(매개변수) {
    실행 코드
}
```

**패키지(Package)**는 관련된 클래스를 그룹화하고 이름 충돌을 방지하기 위한 구조이며, `import`를 사용하면 다른 패키지의 클래스를 간단한 이름으로 사용할 수 있다.

### 핵심 코드

```java
package example;

import java.util.ArrayList;

public class Calculator {

    public int add(int a, int b) {
        return a + b;
    }

}
```

### 핵심 포인트

> `src` 아래의 폴더 구조는 일반적으로 Java의 패키지 구조와 대응하며, `import`를 통해 다른 패키지의 클래스를 현재 코드에서 사용할 수 있다.

## 4. 객체 생성과 생성자

### 개념

클래스가 객체의 구조를 정의한다면, `new`는 해당 클래스를 기반으로 **실제 객체를 생성**할 때 사용한다.

```text
클래스
  ↓
new
  ↓
생성자 호출
  ↓
객체 초기화
  ↓
참조 변수로 객체 사용
```

**생성자(Constructor)**는 객체가 만들어질 때 호출되어 객체의 초기 상태를 설정한다.

### 핵심 코드

```java
public class User {

    String name;
    int age;

    public User() {
    }

    public User(String name) {
        this.name = name;
    }

    public User(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

```java
User user1 = new User();
User user2 = new User("Taein");
User user3 = new User("Taein", 20);
```

같은 이름의 생성자를 매개변수의 개수나 타입을 다르게 정의하는 것을 **생성자 오버로딩**이라고 한다.

### 핵심 포인트

> `new`로 객체를 생성하면 생성자가 호출되고, 생성자 오버로딩을 이용하면 객체를 여러 방식으로 초기화할 수 있다.

# 🐛 문제 해결

## 문제

Java를 설치한 것과 실제 개발 환경에서 Java 명령을 사용할 수 있는 것은 별개의 설정이라는 점이 헷갈렸다.

### 원인

JDK의 역할과 `JAVA_HOME`, `PATH`, `bin` 디렉터리의 관계를 정확히 구분하지 못했다.

### 해결

JDK 설치 후 환경 변수가 어떤 역할을 하는지 실행 흐름을 기준으로 다시 정리했다.

```text
JDK 설치
   ↓
JAVA_HOME → JDK 위치 지정
   ↓
PATH → JDK의 bin 디렉터리 접근
   ↓
java / javac 명령 사용
```

### 배운 점

> 개발 환경 설정은 단순히 JDK를 설치하는 것으로 끝나는 것이 아니라, 운영체제가 `java`, `javac` 등의 실행 파일을 찾을 수 있도록 경로를 구성하는 과정까지 포함한다.
