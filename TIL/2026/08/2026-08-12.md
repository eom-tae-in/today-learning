# 📚 학습 내용

## 1. `static`과 프로그램 실행

### 개념

`static`이 붙은 멤버는 개별 객체가 아니라 **클래스에 속한다.**

따라서 객체를 생성하지 않고 클래스 이름을 통해 접근할 수 있다.

```
Math.random();
```

`Math.random()`은 `static` 메서드이기 때문에 `Math` 객체를 생성하지 않고 바로 호출할 수 있다.

|   |   |   |
|---|---|---|
|구분|static 멤버|인스턴스 멤버|
|소속|클래스|객체|
|객체 생성|필요 없음|필요|
|접근 예|`Math.random()`|`scanner.nextInt()`|

### 동작 흐름

메서드가 호출되면 현재 Thread의 Execution Stack에 해당 메서드를 위한 Stack Frame이 생성된다.

```
main() 실행
    ↓
main Stack Frame 생성
    ↓
메서드 호출
    ↓
새 Stack Frame 생성
    ↓
메서드 실행
    ↓
메서드 종료
    ↓
Stack Frame 제거
```

### 핵심 포인트

> `static`은 클래스에 속하는 개념이고, 실제 메서드가 호출되어 실행되는 정보는 Thread의 Stack에서 관리된다.

## 2. 조건문과 반복문을 이용한 흐름 제어

### 개념

조건문과 반복문은 프로그램의 실행 순서를 제어한다.

- `if`, `switch` : 조건에 따라 실행할 코드 선택
- `for`, `while` : 특정 코드를 반복 실행
- `break` : 현재 반복문 종료
- `continue` : 현재 반복의 나머지를 건너뛰고 다음 반복 진행

특히 `break`와 `continue`는 반복문의 흐름을 중간에서 변경한다.

### 동작 흐름

```
반복 조건 확인
      ↓
   코드 실행
      ↓
 ┌────┴────┐
 ↓         ↓
break   continue
 ↓         ↓
종료     다음 반복
```

`break`는 반복문 자체를 빠져나간다.

```
반복 실행
   ↓
break
   ↓
반복문 종료
   ↓
다음 코드 실행
```

반면 `continue`는 반복문을 종료하지 않는다.

```
반복 실행
   ↓
continue
   ↓
현재 반복의 남은 코드 생략
   ↓
다음 반복
```

### 핵심 포인트

> 조건문은 **어떤 코드를 실행할지 결정**하고, 반복문은 **코드를 반복**하며, `break`와 `continue`는 그 반복의 진행 방향을 제어한다.

## 3. 입력 → 처리 → 출력

### 개념

오늘 배운 `Scanner`, `Math.random()`, 조건·반복문, `printf()`는 하나의 프로그램 실행 흐름으로 연결된다.

|   |   |
|---|---|
|기능|역할|
|`Scanner`|사용자 입력|
|`Math.random()`|난수 생성|
|조건문|값 비교 및 분기|
|반복문|입력·처리 과정 반복|
|`break`|조건 만족 시 반복 종료|
|`printf()`|형식에 맞춰 결과 출력|

### 동작 흐름

```
Math.random()
      ↓
난수 생성
      ↓
Scanner 입력
      ↓
조건문으로 비교
      ↓
결과에 따라 분기
      ↓
반복 또는 종료
      ↓
printf() 출력
```

이러한 흐름을 이용하면 GuessGame처럼 **입력 → 비교 → 반복 → 종료** 구조를 가진 프로그램을 만들 수 있다.

### 핵심 포인트

> 각각의 문법을 따로 사용하는 것이 아니라 입력, 처리, 반복, 출력이라는 하나의 프로그램 흐름으로 연결할 수 있다.

## 4. Thread와 Java 메모리 구조

### 개념

Java 프로그램에서 Thread는 하나의 실행 흐름이며, 각 Thread는 자신만의 **Execution Stack**을 가진다.

반면 객체가 저장되는 Heap은 여러 Thread가 공유한다.

|   |   |   |
|---|---|---|
|영역|주요 내용|공유 여부|
|Execution Stack|지역 변수, 매개변수, 참조값, 메서드 실행 정보|Thread별 개별|
|Stack Frame|하나의 메서드를 실행하기 위한 작업 공간|Stack 내부|
|Heap|`new`로 생성된 객체와 배열|공유|
|Method Area|클래스 메타데이터, 메서드 정보, 런타임 상수 풀 등|공유|

### 동작 흐름

```
Thread
   ↓
Execution Stack
   ↓
main() Stack Frame
   ↓
메서드 호출
   ↓
새 Stack Frame
   ↓
Heap의 객체 참조
   ↓
메서드 종료
   ↓
Stack Frame 제거
```

예를 들어 객체를 생성하면,

```
User user = new User();
```

개념적으로 다음과 같이 이해할 수 있다.

```
Stack                         Heap

user ─────────────────────→ User 객체
참조값                        실제 객체
```

`user`라는 지역 변수에는 객체 자체가 아니라 객체를 가리키는 참조값이 저장된다.

### 핵심 포인트

> Thread마다 Stack은 독립적으로 존재하지만 Heap은 공유하며, Stack의 참조값을 통해 Heap의 객체에 접근할 수 있다.

## 5. String Constant Pool과 GC

### 개념

String은 생성 방식에 따라 객체를 사용하는 방법이 다르다.

```
String a = "hello";
String b = "hello";

String c = new String("hello");
```

`a`와 `b`처럼 문자열 리터럴을 사용하면 String Constant Pool에 같은 문자열이 존재하는지 확인하고 기존 객체를 재사용할 수 있다.

반면 `new String()`은 별도의 String 객체를 Heap에 생성한다.

```
String a = "hello"
        ↓
String Constant Pool 확인
        ↓
기존 "hello"가 있다면 재사용


new String("hello")
        ↓
새로운 String 객체 생성
        ↓
Heap에 저장
```

Java 7부터 String Pool은 Heap 영역에 위치한다.

따라서 현대 Java에서는 String Pool의 문자열도 더 이상 도달할 수 없는 상태가 되면 GC 대상이 될 수 있다.

### 핵심 포인트

> 문자열 리터럴은 String Pool의 객체를 재사용할 수 있고, `new String()`은 별도의 객체를 생성한다. Java 7 이후 String Pool도 Heap에 위치하므로 사용되지 않는 문자열은 GC 대상이 될 수 있다.
