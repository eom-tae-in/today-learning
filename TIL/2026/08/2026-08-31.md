# 📚 학습 내용

## 1. DB 학습 내용 마무리

DB 학습을 마무리하며 개별 문법을 단순히 암기하기보다, 각 문법이 어떤 문제를 해결하는지 기준으로 전체 내용을 연결했다.

### 주요 학습 영역

|영역|주요 내용|사용 목적|
|---|---|---|
|데이터 조회·변경|`SELECT`, `INSERT`, `UPDATE`, `DELETE`|저장된 데이터를 조회하거나 상태를 변경한다.|
|구조 정의|`CREATE`, `ALTER`, `DROP`|테이블과 같은 DB 객체의 구조를 생성·변경·삭제한다.|
|제약조건|`PRIMARY KEY`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE`, `CHECK`|잘못된 데이터가 저장되지 않도록 무결성을 보장한다.|
|데이터 결합|`JOIN`|관련된 여러 테이블의 행을 하나의 결과로 결합한다.|
|결과 활용|서브쿼리, `IN`, `ANY`, `ALL`|다른 쿼리의 결과를 조건이나 데이터 집합으로 사용한다.|
|순위와 범위|Top-N, 순위 함수|정렬된 결과에서 필요한 순위나 범위를 추출한다.|

### JOIN과 서브쿼리의 차이

`JOIN`과 서브쿼리는 모두 여러 데이터 집합을 활용하지만, 사용하는 목적과 표현 방식이 다르다.

| 구분    | JOIN                | 서브쿼리                                |
| ----- | ------------------- | ----------------------------------- |
| 핵심 목적 | 여러 테이블의 열을 결합       | 다른 쿼리의 결과를 조건이나 데이터로 사용             |
| 주요 위치 | `FROM`, `JOIN`      | `SELECT`, `FROM`, `WHERE`, `HAVING` |
| 판단 기준 | 결과에 다른 테이블의 열이 필요한가 | 다른 쿼리의 결과를 기준으로 판단해야 하는가            |

### Top-N 순위 함수

|함수|동점 처리|다음 순위|
|---|---|---|
|`ROW_NUMBER()`|동점이어도 서로 다른 번호 부여|항상 연속|
|`RANK()`|동점에 같은 순위 부여|동점 수만큼 건너뜀|
|`DENSE_RANK()`|동점에 같은 순위 부여|건너뛰지 않음|

> DB 문법은 이름만 암기하는 것이 아니라 데이터 조회·변경, 구조 정의, 무결성 보장, 데이터 결합이라는 목적을 기준으로 구분해야 한다.

## 2. React–Spring Boot–DB의 역할 분리

DB에서 관리되는 데이터는 사용자 화면으로 바로 전달되지 않는다. 프론트엔드와 DB 사이에서 Spring Boot가 요청 검증, 비즈니스 로직 수행과 데이터 접근을 담당한다.

### 구성 요소별 역할

|구성 요소|실행 위치|주요 역할|
|---|---|---|
|React|사용자의 브라우저|화면 렌더링, 사용자 입력 처리, API 호출|
|Spring Boot|백엔드 서버|HTTP 요청 처리, 비즈니스 로직 실행, DB 접근|
|DB|로컬 또는 원격 DB 서버|데이터 저장, 조회, 변경과 무결성 관리|

전체 통신 구조는 다음과 같다.

```text
사용자
    ↓ 화면 조작
브라우저의 React
    ↓ HTTP 요청
Spring Boot
    ↓ JPA·JDBC를 통한 DB 요청
원격 DB
    ↓ 조회·변경 결과
Spring Boot
    ↓ HTTP JSON 응답
React
    ↓
화면 갱신
```

React가 DB에 직접 접근하지 않는 이유는 다음과 같다.

- DB 계정과 비밀번호가 브라우저에 노출될 수 있다.
- 사용자가 비즈니스 규칙을 우회해 데이터를 변경할 수 있다.
- 인증·인가와 입력 검증을 일관되게 적용하기 어렵다.
- 트랜잭션과 데이터 정합성을 백엔드에서 통제할 수 없다.

> React는 DB에 직접 접근하지 않는다. 모든 데이터 요청은 Spring Boot의 API와 비즈니스 로직을 거쳐야 한다.

## 3. Spring Boot와 내장 Tomcat

Spring Boot 자체가 HTTP 요청을 직접 처리하는 웹 서버는 아니다. `spring-boot-starter-web`을 사용하는 일반적인 Spring MVC 애플리케이션에서는 내장 Tomcat이 웹 서버와 Servlet Container 역할을 담당한다.

### 전체 포함 관계

```text
Spring Boot 애플리케이션
├─ Spring Container
│  ├─ Controller
│  ├─ Service
│  └─ Repository
│
└─ Embedded Tomcat
   ├─ Coyote
   ├─ Catalina
   │  └─ DispatcherServlet 관리
   └─ Jasper
```

### Tomcat의 주요 구성 요소

|구성 요소|역할|
|---|---|
|Coyote|네트워크에서 HTTP 요청을 받아 Tomcat 내부로 전달한다.|
|Catalina|Servlet을 생성·초기화·실행하고 생명주기를 관리한다.|
|Jasper|JSP를 Java Servlet 코드로 변환하고 컴파일한다.|

### Servlet과 Servlet Container

Servlet은 HTTP 요청을 받아 처리하고 응답을 생성하는 Java 서버 프로그램의 표준이다. Servlet은 스스로 실행되지 않으며 Catalina와 같은 Servlet Container가 생성하고 실행한다.

Spring MVC의 `DispatcherServlet`도 하나의 Servlet이므로 Catalina의 관리 대상이다.

```text
HTTP 요청
    ↓
Coyote
    ↓
Catalina
    ↓ Filter 실행
DispatcherServlet
```

따라서 Catalina와 `DispatcherServlet`은 같은 역할을 하는 것이 아니다.

- Catalina: Servlet을 실행하고 관리하는 환경
- `DispatcherServlet`: Spring MVC 요청을 중앙에서 분배하는 Servlet
- Jasper: JSP가 필요할 때 이를 Servlet으로 변환하는 엔진

> `DispatcherServlet`은 Catalina 바깥에서 별도로 실행되는 객체가 아니라, Catalina가 관리하는 Spring MVC의 핵심 Servlet이다.

## 4. DispatcherServlet의 요청 처리 과정

Spring MVC에서는 각 Controller가 사용자의 요청을 직접 받지 않는다. 모든 요청을 `DispatcherServlet`이 먼저 받은 뒤 적절한 Controller에 연결한다.

이 구조를 **프런트 컨트롤러 패턴**이라고 한다.

### 요청 처리 흐름

```text
React의 HTTP 요청
    ↓
Tomcat이 요청 수신
    ↓
Catalina가 DispatcherServlet 실행
    ↓
HandlerMapping이 Controller 탐색
    ↓
HandlerAdapter가 Controller 메서드 호출
    ↓
Controller
    ↓
Service
    ↓
Repository
    ↓
JPA·JDBC
    ↓
원격 DB
```

응답은 반대 방향으로 돌아온다.

```text
원격 DB의 처리 결과
    ↓
Repository
    ↓
Service
    ↓
Controller의 응답 DTO
    ↓
HttpMessageConverter
    ↓ Java 객체를 JSON으로 변환
DispatcherServlet
    ↓ HTTP 응답
React
```

### 구성 요소의 역할

|구성 요소|역할|
|---|---|
|`DispatcherServlet`|요청을 중앙에서 받아 전체 처리 흐름을 조정한다.|
|`HandlerMapping`|요청 URL과 HTTP 메서드에 맞는 Controller 메서드를 찾는다.|
|`HandlerAdapter`|찾은 Controller 메서드를 실제로 호출한다.|
|Controller|요청 값을 받고 Service를 호출한 뒤 응답을 반환한다.|
|Service|비즈니스 규칙과 트랜잭션을 처리한다.|
|Repository|JPA·JDBC를 이용해 DB에 접근한다.|
|`HttpMessageConverter`|Java 객체와 JSON 같은 HTTP 본문을 상호 변환한다.|

### 설명용 요청 처리 예제

다음 코드는 실제 실습 코드가 아니라 `DispatcherServlet`이 찾아 실행하는 Controller의 형태를 보여주기 위한 예제다.

```java
@RestController
@RequestMapping("/api/products")
public class ProductController {

    private final ProductService productService;

    public ProductController(ProductService productService) {
        this.productService = productService;
    }

    @GetMapping("/{id}")
    public ProductResponse getProduct(@PathVariable Long id) {
        return productService.getProduct(id);
    }
}
```

React가 다음 요청을 보냈다고 가정한다.

```text
GET /api/products/1
```

`HandlerMapping`은 경로와 HTTP 메서드가 일치하는 `getProduct()`를 찾고, `HandlerAdapter`가 해당 메서드를 실행한다. 반환된 `ProductResponse` 객체는 `HttpMessageConverter`와 Jackson에 의해 JSON으로 변환된다.

```json
{
  "id": 1,
  "name": "상품명",
  "price": 5000
}
```

`@RestController`는 반환값을 JSP 화면 이름으로 해석하지 않고 HTTP 응답 본문에 작성하도록 처리한다.

> `DispatcherServlet`은 직접 비즈니스 로직을 수행하지 않는다. 요청에 적합한 Controller를 찾고 전체 처리 흐름을 연결하는 역할을 담당한다.

## 5. React REST API와 JSP 처리 방식

이미지에 표시된 Jasper는 모든 Spring MVC 요청에서 사용되는 구성 요소가 아니다. Jasper는 JSP 화면을 반환할 때만 처리 과정에 참여한다.

### React 기반 REST API

```text
React
    ↓ API 요청
DispatcherServlet
    ↓
Controller
    ↓
Service → Repository → DB
    ↓
응답 DTO
    ↓
JSON 응답
    ↓
React가 화면 생성
```

화면을 최종적으로 생성하는 주체는 브라우저에서 실행되는 React다. Spring Boot는 화면에 필요한 데이터를 JSON으로 반환한다.

### JSP 기반 MVC

```text
브라우저
    ↓ HTTP 요청
DispatcherServlet
    ↓
Controller
    ↓ View 이름 반환
ViewResolver
    ↓ JSP 탐색
Jasper
    ↓ JSP를 Servlet으로 변환·컴파일
HTML 응답
    ↓
브라우저가 화면 표시
```

JSP는 최초 요청이나 파일 변경 시 Jasper에 의해 Servlet으로 변환되고 컴파일된다. 이후에는 컴파일된 Servlet을 재사용할 수 있다.

### 두 방식 비교

|구분|React + REST API|Spring MVC + JSP|
|---|---|---|
|Controller 형태|주로 `@RestController`|주로 `@Controller`|
|주요 응답|JSON 데이터|완성된 HTML|
|화면 생성 위치|브라우저의 React|백엔드의 JSP|
|Jasper 사용|일반적으로 사용하지 않음|JSP 처리 시 사용|
|반환값 해석|HTTP 응답 본문|View 이름|

React와 Spring Boot를 함께 사용하는 일반적인 구조에서는 Jasper를 핵심 요청 처리 경로에 포함하면 안 된다.

정확한 관계는 다음과 같다.

```text
일반적인 React API 요청
DispatcherServlet → Controller → JSON 응답

JSP 화면 요청
DispatcherServlet → Controller → ViewResolver → Jasper → HTML 응답
```

> Jasper는 JSP 엔진이며, React 기반 REST API의 JSON 응답을 만드는 구성 요소가 아니다.

# 🧠 오늘 이해한 핵심

- Spring Boot는 애플리케이션 실행과 자동 설정을 담당하고, 실제 HTTP 요청은 기본적으로 내장 Tomcat이 받아 처리한다.
- Catalina가 Spring MVC의 `DispatcherServlet`을 관리하며, `DispatcherServlet`은 Controller·Service·Repository로 이어지는 요청 처리 흐름을 조정한다.
- React 기반 REST API에서는 Spring Boot가 JSON을 반환하고 React가 화면을 생성하므로 Jasper가 일반적인 요청 처리에 참여하지 않는다.
- DB는 프론트엔드와 직접 연결되지 않으며, Spring Boot의 비즈니스 로직과 데이터 접근 계층을 통해 사용된다.
