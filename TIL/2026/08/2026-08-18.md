## 1. 함수형 인터페이스

함수형 인터페이스는 **추상 메서드를 하나만 가지는 인터페이스**다. 처리할 동작의 입력과 반환 형태를 인터페이스로 정하고, 실제 동작은 람다 표현식으로 전달할 수 있다.

```java
@FunctionalInterface
interface Calculator {
    int calculate(int left, int right);
}
```

위 인터페이스가 정의하는 동작의 형태는 다음과 같다.

```text
정수 2개 입력
      ↓
calculate(left, right)
      ↓
정수 1개 반환
```

`@FunctionalInterface`는 반드시 작성해야 하는 문법은 아니다. 다만 추상 메서드가 두 개 이상 선언되면 컴파일 오류가 발생하므로 함수형 인터페이스의 조건을 안전하게 지킬 수 있다.

```java
@FunctionalInterface
interface Calculator {
    int calculate(int left, int right);

    default void printDescription() {
        System.out.println("두 값을 계산한다.");
    }
}
```

`default` 메서드와 `static` 메서드는 추상 메서드가 아니므로 여러 개 존재해도 함수형 인터페이스의 조건을 위반하지 않는다.

> 함수형 인터페이스는 동작의 구체적인 내용이 아니라, 동작이 받아야 할 값과 반환해야 할 값의 형태를 정의한다.

## 2. 주요 함수형 인터페이스

Java는 `java.util.function` 패키지에서 자주 사용하는 함수형 인터페이스를 제공한다. 이름을 외우기보다 **입력이 있는지, 무엇을 반환하는지**를 기준으로 구분하는 것이 중요하다.


| 인터페이스               | 입력       | 반환        | 핵심 메서드     | 사용 목적       |
| ------------------- | -------- | --------- | ---------- | ----------- |
| `Predicate<T>`      | `T`      | `boolean` | `test()`   | 조건 검사       |
| `Function<T, R>`    | `T`      | `R`       | `apply()`  | 값 변환        |
| `Consumer<T>`       | `T`      | 없음        | `accept()` | 값 소비        |
| `Supplier<T>`       | 없음       | `T`       | `get()`    | 값 제공        |
| `UnaryOperator<T>`  | `T`      | `T`       | `apply()`  | 같은 타입으로 변환  |
| `BinaryOperator<T>` | `T`, `T` | `T`       | `apply()`  | 두 값을 하나로 결합 |

### 2.1 Predicate: 조건을 검사한다

`Predicate<T>`는 하나의 값을 받아 조건을 검사하고 `boolean`을 반환한다.

```java
Predicate<Integer> isEven = number -> number % 2 == 0;

boolean result = isEven.test(10);
System.out.println(result); // true
```

```text
10 입력
   ↓
10 % 2 == 0 검사
   ↓
true 반환
```

### 2.2 Function: 값을 변환한다

`Function<T, R>`은 `T` 타입 값을 받아 `R` 타입 결과로 변환한다. 입력과 반환 타입은 같을 수도 있고 다를 수도 있다.

```java
Function<String, Integer> getLength = text -> text.length();

int length = getLength.apply("Java");
System.out.println(length); // 4
```

```text
String 입력
   ↓
문자열 길이 계산
   ↓
Integer 반환
```

### 2.3 Consumer: 값을 사용하고 끝낸다

`Consumer<T>`는 값을 받아 사용하지만 결과를 반환하지 않는다. 출력, 저장 또는 상태 변경과 같은 처리에 사용할 수 있다.

```java
Consumer<String> printer = text -> System.out.println(text);

printer.accept("Java"); // Java 출력
```

### 2.4 Supplier: 값을 제공한다

`Supplier<T>`는 입력 없이 값을 만들어 반환한다.

```java
Supplier<Double> randomValue = () -> Math.random();

double value = randomValue.get();
```

```text
Predicate : T를 받아 조건 결과 반환
Function  : T를 받아 R로 변환
Consumer  : T를 받아 사용하고 종료
Supplier  : 입력 없이 T를 제공
```

> 조건 검사인지, 값 변환인지, 값 소비인지, 값 제공인지를 먼저 판단하면 함수형 인터페이스를 구분하기 쉽다.

## 3. 람다 표현식

람다 표현식은 함수형 인터페이스의 추상 메서드를 간결하게 구현하는 문법이다.

### 익명 클래스에서 람다로

익명 클래스로 `Calculator`를 구현하면 다음과 같다.

```java
Calculator add = new Calculator() {
    @Override
    public int calculate(int left, int right) {
        return left + right;
    }
};
```

구현할 추상 메서드가 하나이므로, 메서드명과 형식을 생략하고 동작만 람다로 표현할 수 있다.

```java
Calculator add = (left, right) -> left + right;

int result = add.calculate(10, 20);
System.out.println(result); // 30
```

```text
Calculator 타입 확인
        ↓
calculate(int, int)의 형태 확인
        ↓
(left, right) -> left + right를 구현으로 사용
        ↓
calculate(10, 20) 호출
        ↓
30 반환
```

람다 자체가 독립적인 타입을 가지는 것은 아니다. 대입되는 변수나 전달되는 매개변수를 통해 어떤 함수형 인터페이스를 구현하는지 결정된다.

```java
Predicate<Integer> positive = number -> number > 0;
Function<Integer, Integer> doubleValue = number -> number * 2;
```

두 람다 모두 정수를 입력받지만, 대상 인터페이스에 따라 반환값과 역할이 달라진다.

> 람다는 함수를 새로 만드는 별도의 자료형이 아니라, 함수형 인터페이스의 구현을 간결하게 표현하는 방법이다.

## 4. Stream API

Stream API는 컬렉션 등의 데이터를 **선택하고, 변환하고, 결과로 만드는 과정**을 선언적으로 표현한다.

기존 반복문은 데이터를 어떻게 순회할지를 직접 작성한다.

```java
List<Integer> result = new ArrayList<>();

for (int number : numbers) {
    if (number % 2 == 0) {
        result.add(number * number);
    }
}
```

스트림에서는 원하는 처리 과정에 집중한다.

```java
List<Integer> result = numbers.stream()
        .filter(number -> number % 2 == 0)
        .map(number -> number * number)
        .toList();
```

### 4.1 스트림 처리 단계

```text
데이터 소스
   ↓ stream()
스트림 생성
   ↓
중간 연산
filter · map · sorted · distinct
   ↓
최종 연산
toList · forEach · reduce · count
   ↓
결과 생성
```

- 중간 연산은 새로운 스트림을 반환한다.
- 중간 연산은 최종 연산이 호출될 때까지 실제 처리를 미룬다.
- 최종 연산이 실행되면 스트림이 소비된다.
- 한 번 소비한 스트림은 다시 사용할 수 없다.
- 스트림은 원본 컬렉션을 직접 변경하지 않는다.

### 4.2 함수형 인터페이스와 스트림의 연결


| Stream 연산   | 전달받는 인터페이스          | 람다의 역할        |
| ----------- | ------------------- | ------------- |
| `filter()`  | `Predicate<T>`      | 요소를 남길지 검사    |
| `map()`     | `Function<T, R>`    | 요소를 다른 값으로 변환 |
| `forEach()` | `Consumer<T>`       | 각 요소를 사용      |
| `reduce()`  | `BinaryOperator<T>` | 두 값을 하나로 누적   |

다음은 각 연산이 연결되는 과정을 보여주는 개념 예제다.

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5, 6);

List<Integer> result = numbers.stream()
        .filter(number -> number % 2 == 0)
        .map(number -> number * number)
        .toList();

result.forEach(System.out::println);
```

```text
[1, 2, 3, 4, 5, 6]
          ↓ filter(Predicate)
[2, 4, 6]
          ↓ map(Function)
[4, 16, 36]
          ↓ toList()
List<Integer> 생성
          ↓ forEach(Consumer)
4, 16, 36 출력
```

### 4.3 reduce로 하나의 값 만들기

`reduce()`는 여러 요소를 하나의 결과로 누적한다.

```java
int sum = numbers.stream()
        .reduce(0, (total, number) -> total + number);

System.out.println(sum); // 21
```

```text
초깃값 0
  ↓ 0 + 1
1
  ↓ 1 + 2
3
  ↓ 3 + 3
6
  ↓ 반복
21
```

### 4.4 메서드 참조

람다가 기존 메서드를 그대로 호출하기만 한다면 메서드 참조로 줄일 수 있다.

```java
result.forEach(number -> System.out.println(number));
result.forEach(System.out::println);
```

> 스트림은 반복문을 단순히 짧게 쓰는 기능이 아니라, 데이터 처리 단계를 함수형 인터페이스로 연결하는 방식이다.

## 5. 제네릭과 Wrapper Class

### 5.1 제네릭이 필요한 이유

제네릭은 클래스, 인터페이스 또는 메서드에서 사용할 타입을 외부에서 지정하는 기능이다.

제네릭을 사용하지 않으면 값을 꺼낼 때 직접 형변환해야 하고, 잘못된 타입이 들어가도 실행하기 전까지 발견하기 어렵다.

```java
List values = new ArrayList();
values.add("Java");

String value = (String) values.get(0);
```

제네릭으로 타입을 지정하면 컴파일 시점에 잘못된 타입을 확인하고, 값을 꺼낼 때 형변환을 생략할 수 있다.

```java
List<String> values = new ArrayList<>();
values.add("Java");

String value = values.get(0);
```

```text
List<String> 선언
      ↓
String만 저장 가능
      ↓
컴파일 시점에 타입 검사
      ↓
꺼낼 때 형변환 불필요
```

| 기호  | 의미      | 대표 사용 위치   |
| --- | ------- | ---------- |
| `T` | Type    | 일반적인 타입    |
| `E` | Element | 컬렉션 요소     |
| `K` | Key     | Map의 Key   |
| `V` | Value   | Map의 Value |
| `N` | Number  | 숫자 타입      |
| `R` | Result  | 반환 타입      |

이 문자는 Java가 강제하는 키워드가 아니라 역할을 쉽게 알아보기 위한 관례다.

### 5.2 Boxing과 Unboxing

제네릭에는 `int`, `char` 같은 기본 타입을 직접 사용할 수 없다. 기본 타입을 객체로 다루려면 Wrapper Class를 사용해야 한다.

| 기본 타입     | Wrapper Class |
| --------- | ------------- |
| `byte`    | `Byte`        |
| `short`   | `Short`       |
| `int`     | `Integer`     |
| `long`    | `Long`        |
| `float`   | `Float`       |
| `double`  | `Double`      |
| `char`    | `Character`   |
| `boolean` | `Boolean`     |

```text
기본 타입
   ↓ Boxing
Wrapper Class 객체
   ↓ Unboxing
기본 타입
```

```java
Integer boxedNumber = 10; // int → Integer: Autoboxing
int number = boxedNumber; // Integer → int: Auto-unboxing
```

Wrapper Class는 객체이므로 `null`을 가질 수 있다. `null`인 Wrapper 객체를 기본 타입으로 Unboxing하면 `NullPointerException`이 발생한다.

```java
Integer boxedNumber = null;
int number = boxedNumber; // NullPointerException
```

> 제네릭은 타입을 안전하게 제한하고, Wrapper Class는 기본 타입을 제네릭에서 사용할 수 있는 객체 타입으로 연결한다.

## 6. Collection API

Collection API는 여러 객체를 저장하고 관리하기 위한 자료구조와 기능을 제공한다. 데이터의 순서, 중복 허용 여부, 저장 형태에 따라 적절한 구조를 선택한다.

### 6.1 List, Set, Map 비교

| 구분     | 저장 형태     | 중복        | 순서         | 접근 방식  |
| ------ | --------- | --------- | ---------- | ------ |
| `List` | 값         | 허용        | 입력 순서 유지   | 인덱스    |
| `Set`  | 값         | 허용하지 않음   | 구현체에 따라 다름 | 요소 기준  |
| `Map`  | Key-Value | Key 중복 불가 | 구현체에 따라 다름 | Key 기준 |

`Map`은 `Collection` 인터페이스를 직접 상속하지 않지만, 여러 데이터를 관리하는 Collection API의 주요 자료구조로 함께 사용된다.

### 6.2 List: 순서와 중복이 필요할 때

```java
List<String> names = new ArrayList<>();

names.add("Kim");
names.add("Lee");
names.add("Kim");

System.out.println(names); // [Kim, Lee, Kim]
System.out.println(names.get(1)); // Lee
```

```text
입력 순서 유지
Kim → Lee → Kim

중복 허용
Kim이 두 번 저장됨

인덱스 접근
names.get(1) → Lee
```

### 6.3 Set: 고유한 값이 필요할 때

```java
Set<String> names = new HashSet<>();

names.add("Kim");
names.add("Lee");
names.add("Kim");

System.out.println(names.size()); // 2
```

같은 값인 `Kim`을 두 번 추가해도 한 번만 저장된다.

| 구현체             | 순서 특징       |
| --------------- | ----------- |
| `HashSet`       | 순서를 보장하지 않음 |
| `LinkedHashSet` | 입력 순서를 유지함  |
| `TreeSet`       | 정렬된 순서를 유지함 |

### 6.4 Map: Key로 Value를 관리할 때

```java
Map<String, Integer> scores = new HashMap<>();

scores.put("Kim", 90);
scores.put("Lee", 80);
scores.put("Kim", 100);

System.out.println(scores.get("Kim")); // 100
```

```text
"Kim" → 90 저장
      ↓
같은 Key "Kim" → 100 저장
      ↓
기존 Value를 100으로 변경
```

- Key는 중복될 수 없다.
- Value는 중복될 수 있다.
- 같은 Key로 다시 저장하면 기존 Value가 교체된다.

### 6.5 컬렉션 선택 기준

```text
입력 순서와 중복이 모두 필요한가?
        └─ Yes → List

중복 없는 고유한 값이 필요한가?
        └─ Yes → Set

Key를 기준으로 값을 저장하고 조회해야 하는가?
        └─ Yes → Map
```

> 컬렉션은 익숙한 구현체를 먼저 선택하는 것이 아니라, 데이터에 필요한 순서·중복·조회 기준을 확인한 뒤 선택한다.

# 🔗 오늘 배운 개념의 연결

각 개념은 독립적으로 끝나는 것이 아니라 다음과 같이 연결된다.

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5, 6);

Predicate<Integer> isEven = number -> number % 2 == 0;
Function<Integer, Integer> square = number -> number * number;

List<Integer> result = numbers.stream()
        .filter(isEven)
        .map(square)
        .toList();

result.forEach(System.out::println);
```

```text
List<Integer>
제네릭으로 Integer 타입 제한
        ↓
Predicate<Integer>
짝수 여부 검사
        ↓
Function<Integer, Integer>
숫자를 제곱값으로 변환
        ↓
Stream
filter → map → toList 순서로 처리
        ↓
Consumer 역할의 forEach
각 결과 출력
```

이 코드 하나에서 오늘 배운 개념이 모두 연결된다.

| 개념              | 코드에서의 역할                  |
| --------------- | ------------------------- |
| `List<Integer>` | 여러 정수를 순서대로 저장            |
| 제네릭             | 컬렉션과 함수형 인터페이스가 사용할 타입 제한 |
| `Predicate`     | `filter()`에 전달할 조건 정의     |
| `Function`      | `map()`에 전달할 변환 규칙 정의     |
| 람다              | 조건과 변환 동작 구현              |
| Stream          | 각 처리 단계를 순서대로 연결          |
| `forEach()`     | 최종 결과 소비                  |

---

# 🧠 오늘 이해한 핵심

- 함수형 인터페이스가 처리 동작의 형태를 정의하고, 람다는 그 동작을 구현한다.
- Stream API는 `Predicate`, `Function`, `Consumer` 등의 동작을 연결해 컬렉션 데이터를 처리한다.
- 제네릭과 Wrapper Class로 타입을 안전하게 관리하고, 데이터의 특성에 따라 `List`, `Set`, `Map`을 선택한다.
