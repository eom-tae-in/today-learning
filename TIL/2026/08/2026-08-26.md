# 📚 학습 내용

## 1. 집계 함수와 GROUP BY

### 필요한 이유

일반적인 `SELECT`는 조건을 만족하는 개별 행을 그대로 조회한다.

하지만 다음과 같은 질문에 답하려면 여러 행을 하나의 기준으로 묶고 계산해야 한다.

- 부서별 직원은 몇 명인가?
- 직급별 평균 급여는 얼마인가?
- 부서별 최고 급여는 얼마인가?

이때 집계 함수와 `GROUP BY`를 사용한다.

### 집계 함수

집계 함수는 여러 행의 값을 계산하여 하나의 결과를 반환한다.

|함수|역할|`NULL` 처리|
|---|---|---|
|`COUNT(*)`|조회된 전체 행의 수를 계산한다.|행 자체를 세므로 특정 컬럼의 `NULL` 여부와 관계없다.|
|`COUNT(컬럼)`|해당 컬럼에 값이 있는 행의 수를 계산한다.|`NULL`인 값은 제외한다.|
|`SUM(컬럼)`|값의 합계를 계산한다.|`NULL`을 제외한다.|
|`AVG(컬럼)`|값의 평균을 계산한다.|`NULL`을 제외한다.|
|`MAX(컬럼)`|가장 큰 값을 반환한다.|`NULL`을 제외한다.|
|`MIN(컬럼)`|가장 작은 값을 반환한다.|`NULL`을 제외한다.|

아래 코드는 전체 직원의 수와 급여 통계를 조회하는 설명용 예제다.

```sql
SELECT
    COUNT(*) AS employee_count,
    SUM(salary) AS total_salary,
    AVG(salary) AS average_salary,
    MAX(salary) AS max_salary,
    MIN(salary) AS min_salary
FROM employee;
```

집계 함수만 사용하고 `GROUP BY`를 작성하지 않으면 조회된 전체 행이 하나의 그룹처럼 계산된다.

### GROUP BY의 동작

`GROUP BY`는 지정한 컬럼의 값이 같은 행끼리 묶는다. 이후 각 그룹에 집계 함수를 적용하여 그룹마다 하나의 결과 행을 만든다.

```text
employee 테이블 조회
    ↓
dept_id가 같은 직원끼리 분류
    ↓
각 부서 그룹에 COUNT 적용
    ↓
부서별 결과 행 생성
```

부서 번호별 직원 수를 구하는 설명용 예제는 다음과 같다.

```sql
SELECT
    dept_id,
    COUNT(*) AS employee_count
FROM employee
GROUP BY dept_id;
```

예를 들어 직원 데이터가 다음과 같다고 가정한다.

|emp_id|emp_name|dept_id|salary|
|---|---|---|---|
|1|김민수|10|3000|
|2|이서연|10|4200|
|3|박지훈|20|3200|
|4|최유진|20|5000|
|5|정하늘|30|4000|
|6|오세훈|`NULL`|2400|

위 쿼리의 결과는 다음과 같은 형태가 된다.

|dept_id|employee_count|
|---|---|
|`NULL`|1|
|10|2|
|20|2|
|30|1|

`GROUP BY`에서는 `NULL`도 하나의 그룹으로 묶인다. 따라서 소속 부서가 없는 오세훈도 `NULL` 그룹으로 집계된다.

### 여러 컬럼으로 그룹화

여러 컬럼을 `GROUP BY`에 작성하면 모든 컬럼 값의 조합이 같은 행끼리 하나의 그룹이 된다.

```sql
SELECT
    dept_id,
    position,
    COUNT(*) AS employee_count
FROM employee
GROUP BY dept_id, position
ORDER BY dept_id, position;
```

이 쿼리는 다음과 같은 조합을 각각 다른 그룹으로 처리한다.

```sql
(10, 사원)
(10, 대리)
(20, 사원)
(20, 과장)
```

부서 번호가 같더라도 직급이 다르면 서로 다른 그룹이 된다.

### SELECT에 작성할 수 있는 컬럼

`GROUP BY`를 사용한 `SELECT` 절에는 일반적으로 다음 두 종류의 값만 작성해야 한다.

1. `GROUP BY`에 포함된 컬럼
2. 집계 함수로 계산한 값

다음 쿼리는 올바르지 않다.

```sql
SELECT
    dept_id,
    emp_name,
    COUNT(*)
FROM employee
GROUP BY dept_id;
```

하나의 부서에는 여러 직원이 있을 수 있다. 그런데 부서별 결과 한 행에 `emp_name`을 하나만 출력하면 DB는 어떤 직원의 이름을 선택해야 할지 명확하게 결정할 수 없다.

올바른 형태는 다음과 같다.

```sql
SELECT
    dept_id,
    COUNT(*) AS employee_count
FROM employee
GROUP BY dept_id;
```

MySQL 설정에 따라 잘못된 쿼리가 실행될 수도 있지만, 결과의 의미가 불명확하므로 `GROUP BY`에 없는 일반 컬럼은 조회하지 않는 것이 원칙이다.

> `GROUP BY`는 행을 단순히 정렬하는 문법이 아니라, 같은 기준의 행을 하나의 집계 단위로 묶는 문법이다.

## 2. WHERE와 HAVING의 차이

`GROUP BY`를 사용하면 조건을 적용하는 시점도 구분해야 한다.

- 그룹화하기 전에 개별 행을 제거하려면 `WHERE`
- 그룹화한 후 집계 결과를 제거하려면 `HAVING`

|구분|`WHERE`|`HAVING`|
|---|---|---|
|적용 시점|`GROUP BY` 이전|`GROUP BY` 이후|
|조건 대상|개별 행|집계된 그룹|
|대표 조건|`salary >= 3000`|`COUNT(*) >= 2`|
|집계 함수 조건|일반적으로 사용할 수 없음|사용할 수 있음|

### WHERE로 개별 행 필터링

급여가 3000 이상인 직원만 대상으로 부서별 평균 급여를 구한다.

```sql
SELECT
    dept_id,
    AVG(salary) AS average_salary
FROM employee
WHERE salary >= 3000
GROUP BY dept_id;
```

`WHERE`에서 제외된 직원은 그룹에 포함되지 않으므로 평균 계산에도 참여하지 않는다.

### HAVING으로 집계 결과 필터링

직원이 2명 이상인 부서만 조회한다.

```sql
SELECT
    dept_id,
    COUNT(*) AS employee_count
FROM employee
WHERE dept_id IS NOT NULL
GROUP BY dept_id
HAVING COUNT(*) >= 2;
```

동작 순서는 다음과 같다.

```text
employee 테이블 조회
    ↓ WHERE
소속 부서가 있는 직원만 유지
    ↓ GROUP BY
dept_id별로 그룹화
    ↓ HAVING
직원이 2명 이상인 그룹만 유지
    ↓ SELECT
부서 번호와 직원 수 반환
```

### SQL의 논리적 실행 순서

SQL은 작성된 순서와 개념적인 실행 순서가 다르다.

```text
FROM
    ↓
JOIN / ON
    ↓
WHERE
    ↓
GROUP BY
    ↓
HAVING
    ↓
SELECT
    ↓
DISTINCT
    ↓
ORDER BY
    ↓
LIMIT
```

이 순서를 기준으로 보면 `WHERE`에서 집계 함수를 사용할 수 없는 이유를 이해할 수 있다. `WHERE`가 실행되는 시점에는 아직 `GROUP BY`와 집계가 수행되지 않았기 때문이다.

> 개별 행의 조건은 `WHERE`, 그룹 계산 결과의 조건은 `HAVING`에 작성한다.

## 3. JOIN으로 여러 테이블 연결하기

### 필요한 이유

관계형 데이터베이스는 데이터 중복을 줄이고 일관성을 관리하기 위해 정보를 여러 테이블로 나누어 저장한다.

예를 들어 직원 테이블에 부서명을 직접 반복해서 저장하지 않고 부서 번호만 저장할 수 있다.

```text
department
- dept_id: 부서를 식별하는 기본 키
- dept_name: 부서명

employee
- emp_id: 직원을 식별하는 기본 키
- emp_name: 직원명
- dept_id: 소속 부서를 가리키는 외래 키
```

두 테이블의 관계는 다음과 같다.

```text
employee.dept_id
    ↓ 참조
department.dept_id
```

직원 이름과 부서명을 함께 조회하려면 `employee.dept_id`와 `department.dept_id`를 기준으로 두 테이블을 연결해야 한다.

### 기본 JOIN 문법

다음은 설명용 예제다.

```sql
SELECT
    e.emp_name,
    d.dept_name
FROM employee AS e
INNER JOIN department AS d
    ON e.dept_id = d.dept_id;
```

각 부분의 역할은 다음과 같다.

|문법|역할|
|---|---|
|`employee AS e`|직원 테이블에 `e`라는 별칭을 부여한다.|
|`department AS d`|부서 테이블에 `d`라는 별칭을 부여한다.|
|`INNER JOIN`|두 테이블에서 조건이 일치하는 행만 연결한다.|
|`ON`|어떤 컬럼을 기준으로 행을 연결할지 지정한다.|
|`e.dept_id = d.dept_id`|직원의 부서 번호와 부서의 기본 키가 같은 행을 연결한다.|

테이블 별칭을 사용하면 컬럼이 어느 테이블에 속하는지 분명하게 표현할 수 있다.

### JOIN 조건이 필요한 이유

JOIN 조건을 빠뜨리면 두 테이블의 가능한 모든 행 조합이 만들어질 수 있다.

직원이 6명이고 부서가 4개라면 다음과 같이 계산된다.

```text
직원 6행
    ×
부서 4행
    ↓
총 24행
```

이처럼 모든 조합이 만들어지는 결과를 카테시안 곱이라고 한다. 의도적으로 모든 조합이 필요한 상황이 아니라면 `ON` 조건을 정확히 작성해야 한다.

### JOIN 결과의 행 수

JOIN은 한 행과 한 행만 연결하는 문법이 아니다. 조건에 일치하는 행의 수만큼 결과 행이 만들어진다.

|관계|예시|JOIN 결과|
|---|---|---|
|일대일 `1:1`|직원과 사원증|기준 행 하나당 최대 한 행이 연결된다.|
|일대다 `1:N`|부서와 직원|부서가 소속 직원 수만큼 반복될 수 있다.|
|다대다 `N:M`|직원과 프로젝트|중간 테이블을 거쳐 여러 행이 만들어질 수 있다.|

따라서 JOIN 결과에 같은 부서나 직원이 여러 번 보인다고 해서 반드시 잘못된 중복은 아니다. 실제 테이블 관계가 일대다라면 정상적인 결과일 수 있다.

> JOIN을 작성하기 전에는 연결할 컬럼뿐만 아니라 테이블 사이의 관계가 `1:1`, `1:N`, `N:M` 중 무엇인지 확인해야 한다.

## 4. INNER JOIN과 OUTER JOIN

JOIN은 연결되지 않은 행을 결과에 포함할 것인지에 따라 구분할 수 있다.

|JOIN 종류|결과에 포함되는 데이터|
|---|---|
|`INNER JOIN`|양쪽 테이블에서 조건이 일치하는 행만 포함한다.|
|`LEFT OUTER JOIN`|왼쪽 테이블의 모든 행과 오른쪽에서 일치하는 행을 포함한다.|
|`RIGHT OUTER JOIN`|오른쪽 테이블의 모든 행과 왼쪽에서 일치하는 행을 포함한다.|
|`FULL OUTER JOIN`|양쪽 테이블의 모든 행을 포함한다.|

`OUTER`는 생략할 수 있다.

```sql
LEFT OUTER JOIN  = LEFT JOIN
RIGHT OUTER JOIN = RIGHT JOIN
```

### INNER JOIN

`INNER JOIN`은 양쪽 테이블에서 연결 조건이 일치하는 행만 반환한다. `INNER`를 생략하고 `JOIN`만 작성해도 같은 의미다.

```sql
SELECT
    e.emp_id,
    e.emp_name,
    d.dept_name
FROM employee AS e
INNER JOIN department AS d
    ON e.dept_id = d.dept_id
ORDER BY e.emp_id;
```

예제 데이터 기준 결과는 다음과 같다.

|emp_id|emp_name|dept_name|
|---|---|---|
|1|김민수|개발팀|
|2|이서연|개발팀|
|3|박지훈|기획팀|
|4|최유진|기획팀|
|5|정하늘|인사팀|

다음 데이터는 결과에서 제외된다.

- 오세훈은 `dept_id`가 `NULL`이므로 연결되는 부서가 없다.
- 디자인팀은 소속 직원이 없으므로 연결되는 직원이 없다.

```text
employee 행
    ↓ 부서 번호가 일치하는가?
일치함 ── 결과에 포함
일치하지 않음 ── 결과에서 제외
```

### LEFT JOIN

`LEFT JOIN`은 왼쪽 테이블의 모든 행을 먼저 유지한다. 오른쪽에 일치하는 행이 없으면 오른쪽 테이블의 컬럼을 `NULL`로 채운다.

모든 직원을 빠짐없이 조회하려면 `employee`를 왼쪽에 둔다.

```sql
SELECT
    e.emp_id,
    e.emp_name,
    d.dept_name
FROM employee AS e
LEFT JOIN department AS d
    ON e.dept_id = d.dept_id
ORDER BY e.emp_id;
```

|emp_id|emp_name|dept_name|
|---|---|---|
|1|김민수|개발팀|
|2|이서연|개발팀|
|3|박지훈|기획팀|
|4|최유진|기획팀|
|5|정하늘|인사팀|
|6|오세훈|`NULL`|

반대로 직원이 없는 부서까지 조회하려면 `department`를 왼쪽에 둔다.

```sql
SELECT
    d.dept_name,
    e.emp_name
FROM department AS d
LEFT JOIN employee AS e
    ON d.dept_id = e.dept_id
ORDER BY d.dept_id, e.emp_id;
```

|dept_name|emp_name|
|---|---|
|개발팀|김민수|
|개발팀|이서연|
|기획팀|박지훈|
|기획팀|최유진|
|인사팀|정하늘|
|디자인팀|`NULL`|

`LEFT JOIN`에서는 왼쪽 테이블이 결과의 기준이 된다.

### RIGHT JOIN

`RIGHT JOIN`은 오른쪽 테이블의 모든 행을 유지한다.

```sql
SELECT
    e.emp_name,
    d.dept_name
FROM employee AS e
RIGHT JOIN department AS d
    ON e.dept_id = d.dept_id;
```

위 쿼리는 테이블 순서를 바꾼 다음 `LEFT JOIN`을 사용해 표현할 수도 있다.

```sql
SELECT
    e.emp_name,
    d.dept_name
FROM department AS d
LEFT JOIN employee AS e
    ON d.dept_id = e.dept_id;
```

두 쿼리의 핵심 의미는 같다. 실무에서는 조회 기준을 왼쪽에 배치하여 읽는 방향을 통일하기 쉬운 `LEFT JOIN`을 자주 사용한다.

### FULL OUTER JOIN

`FULL OUTER JOIN`은 양쪽 테이블의 모든 행을 유지한다.

```sql
SELECT
    e.emp_name,
    d.dept_name
FROM employee AS e
FULL OUTER JOIN department AS d
    ON e.dept_id = d.dept_id;
```

결과에는 다음 데이터가 모두 포함된다.

- 부서가 존재하는 직원
- 소속 부서가 없는 직원
- 소속 직원이 없는 부서

MySQL과 MariaDB는 `FULL OUTER JOIN` 문법을 직접 지원하지 않는다. 필요한 경우 `LEFT JOIN`, `RIGHT JOIN`, `UNION` 등을 조합하여 같은 결과를 구성해야 한다.

> `INNER JOIN`과 `OUTER JOIN`의 핵심 차이는 연결되지 않은 행을 결과에 남길 것인지다.

## 5. OUTER JOIN에서 ON과 WHERE의 차이

`LEFT JOIN`에서는 오른쪽 테이블에 대한 조건을 `ON`에 작성할 때와 `WHERE`에 작성할 때 결과가 달라질 수 있다.

요구사항이 다음과 같다고 가정한다.

> 모든 부서를 조회하되, 급여가 4000 이상인 직원만 연결한다.

### 조건을 ON에 작성한 경우

```sql
SELECT
    d.dept_name,
    e.emp_name,
    e.salary
FROM department AS d
LEFT JOIN employee AS e
    ON d.dept_id = e.dept_id
   AND e.salary >= 4000
ORDER BY d.dept_id;
```

|dept_name|emp_name|salary|
|---|---|---|
|개발팀|이서연|4200|
|기획팀|최유진|5000|
|인사팀|정하늘|4000|
|디자인팀|`NULL`|`NULL`|

급여 조건은 오른쪽에서 연결할 직원을 제한한다. 왼쪽 테이블의 모든 부서를 유지한다는 `LEFT JOIN`의 동작은 그대로 유지된다.

### 조건을 WHERE에 작성한 경우

```sql
SELECT
    d.dept_name,
    e.emp_name,
    e.salary
FROM department AS d
LEFT JOIN employee AS e
    ON d.dept_id = e.dept_id
WHERE e.salary >= 4000
ORDER BY d.dept_id;
```

|dept_name|emp_name|salary|
|---|---|---|
|개발팀|이서연|4200|
|기획팀|최유진|5000|
|인사팀|정하늘|4000|

디자인팀의 직원 급여는 `NULL`이다. `NULL >= 4000`은 `TRUE`가 아니므로 `WHERE` 단계에서 디자인팀 행이 제거된다.

```text
LEFT JOIN 실행
    ↓
디자인팀 행 생성
employee 컬럼은 NULL
    ↓ WHERE e.salary >= 4000
조건이 TRUE가 아님
    ↓
디자인팀 행 제거
```

|조건 위치|의미|왼쪽 행 유지|
|---|---|---|
|`ON`|오른쪽에서 연결할 행을 제한한다.|유지된다.|
|`WHERE`|JOIN이 끝난 전체 결과를 필터링한다.|조건에 따라 제거될 수 있다.|

모든 조건을 무조건 `ON`에 작성해야 하는 것은 아니다. 어떤 데이터를 남겨야 하는지에 따라 조건 위치를 결정해야 한다.

> `ON`은 행을 어떻게 연결할지 결정하고, `WHERE`는 연결이 끝난 결과에서 어떤 행을 남길지 결정한다.

## 6. JOIN과 GROUP BY 함께 사용하기

실제 조회에서는 테이블을 연결한 뒤 그룹별 통계를 계산하는 경우가 많다.

예를 들어 부서 번호 대신 부서명을 출력하면서 부서별 직원 수를 계산하려면 `JOIN`과 `GROUP BY`를 함께 사용해야 한다.

### 직원이 있는 부서만 집계

```sql
SELECT
    d.dept_id,
    d.dept_name,
    COUNT(*) AS employee_count
FROM department AS d
INNER JOIN employee AS e
    ON d.dept_id = e.dept_id
GROUP BY d.dept_id, d.dept_name
ORDER BY d.dept_id;
```

`INNER JOIN`을 사용했기 때문에 직원이 없는 디자인팀은 JOIN 단계에서 제외된다.

### 직원이 없는 부서까지 집계

```sql
SELECT
    d.dept_id,
    d.dept_name,
    COUNT(e.emp_id) AS employee_count
FROM department AS d
LEFT JOIN employee AS e
    ON d.dept_id = e.dept_id
GROUP BY d.dept_id, d.dept_name
ORDER BY d.dept_id;
```

|dept_id|dept_name|employee_count|
|---|---|---|
|10|개발팀|2|
|20|기획팀|2|
|30|인사팀|1|
|40|디자인팀|0|

여기서는 `COUNT(*)`가 아니라 `COUNT(e.emp_id)`를 사용해야 한다.

직원이 없는 디자인팀도 `LEFT JOIN`에 의해 결과 행 하나가 만들어진다. 이때 직원 컬럼은 `NULL`이다.

```sql
디자인팀
    ↓ LEFT JOIN
직원이 없어도 결과 행 하나 생성
    ↓
e.emp_id = NULL
    ├─ COUNT(*)       → 행 자체를 세므로 1
    └─ COUNT(e.emp_id) → NULL을 제외하므로 0
```

OUTER JOIN에서 연결된 상대의 수를 세려면 상대 테이블의 `NULL`이 될 수 없는 기본 키를 `COUNT`하는 것이 안전하다.

### JOIN 후 집계값이 증가하는 문제

JOIN 결과는 관계에 따라 행이 증가할 수 있다.

한 직원이 프로젝트 두 개에 참여한다면 직원과 프로젝트를 JOIN했을 때 해당 직원은 두 행으로 나타난다.

|emp_name|salary|project_name|
|---|---|---|
|김민수|3000|쇼핑몰 개편|
|김민수|3000|모바일 앱|

이 결과에서 급여를 단순히 `SUM`하면 김민수의 급여가 두 번 더해진다.

따라서 집계 전에 다음을 확인해야 한다.

1. 원본 데이터에서 집계 대상의 단위가 무엇인가?
2. JOIN 결과 한 행은 무엇을 의미하는가?
3. JOIN으로 같은 집계 대상이 여러 번 반복되지 않는가?
4. 필요한 경우 테이블별로 먼저 집계한 후 결과를 JOIN해야 하는가?

단순히 `DISTINCT`를 추가해서 문제를 숨기면 안 된다. 중복처럼 보이는 행이 실제 관계를 나타내는 정상적인 행일 수 있기 때문이다.

> JOIN과 GROUP BY를 함께 사용할 때는 문법보다 먼저 최종 결과 한 행의 의미와 집계 단위를 정해야 한다.

## 7. NULL 처리와 JOIN 결과 확인

### NULL 비교

`NULL`은 값이 없거나 알 수 없음을 의미한다. 일반 비교 연산자로 비교하지 않고 `IS NULL` 또는 `IS NOT NULL`을 사용한다.

잘못된 조건은 다음과 같다.

```sql
WHERE dept_id = NULL
```

올바른 조건은 다음과 같다.

```sql
WHERE dept_id IS NULL
```

```sql
WHERE dept_id IS NOT NULL
```

### 연결되지 않은 데이터 찾기

`LEFT JOIN` 후 오른쪽 테이블의 기본 키가 `NULL`인 행을 찾으면 연결되지 않은 데이터를 조회할 수 있다.

직원이 없는 부서를 찾는 설명용 예제는 다음과 같다.

```sql
SELECT
    d.dept_id,
    d.dept_name
FROM department AS d
LEFT JOIN employee AS e
    ON d.dept_id = e.dept_id
WHERE e.emp_id IS NULL;
```

동작 과정은 다음과 같다.

```text
모든 부서를 기준으로 LEFT JOIN
    ↓
직원이 없는 부서의 employee 컬럼은 NULL
    ↓
WHERE e.emp_id IS NULL
    ↓
직원이 없는 부서만 반환
```

### COALESCE로 NULL 표시 변경

연결되는 값이 없을 때 `NULL` 대신 다른 값을 표시하려면 `COALESCE`를 사용할 수 있다.

```sql
SELECT
    e.emp_name,
    COALESCE(d.dept_name, '미배정') AS dept_name
FROM employee AS e
LEFT JOIN department AS d
    ON e.dept_id = d.dept_id;
```

`COALESCE`는 전달된 값을 왼쪽부터 확인하여 처음으로 `NULL`이 아닌 값을 반환한다.

오세훈처럼 소속 부서가 없는 직원은 부서명이 `미배정`으로 표시된다.

> OUTER JOIN에서는 연결되지 않은 데이터가 `NULL`로 표현되므로 `COUNT`, 조건식, 출력값에서 `NULL`을 어떻게 처리할지 함께 결정해야 한다.

# 🧠 오늘 이해한 핵심

- `GROUP BY`는 같은 값을 가진 행을 하나의 집계 단위로 묶고, 집계 함수는 각 그룹의 개수·합계·평균 등을 계산한다.
- `JOIN`은 관련 컬럼을 기준으로 테이블을 연결하며, `INNER JOIN`과 `OUTER JOIN`은 연결되지 않은 행을 결과에 포함할지에 따라 구분된다.
- `LEFT JOIN`의 기준은 왼쪽 테이블이므로, 무엇을 빠짐없이 조회해야 하는지 먼저 결정하고 테이블의 위치를 정해야 한다.
- `JOIN`과 `GROUP BY`를 함께 사용할 때는 `NULL` 처리뿐 아니라 JOIN으로 행이 반복되어 집계값이 증가하지 않는지도 확인해야 한다.

# 🔍 복습할 부분

- `WHERE`와 `HAVING`을 SQL의 논리적 실행 순서에 따라 다시 구분한다.
- 동일한 예제 데이터를 `INNER JOIN`과 `LEFT JOIN`으로 조회하여 결과에서 제외되거나 유지되는 행을 비교한다.
- `LEFT JOIN`에서 오른쪽 테이블 조건을 `ON`과 `WHERE`에 각각 작성하고 결과 차이를 확인한다.
- 직원이 없는 부서를 집계할 때 `COUNT(*)`와 `COUNT(상대 테이블 PK)`의 결과가 다른 이유를 다시 확인한다.
