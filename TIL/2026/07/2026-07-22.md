## ✅ 잘한 점

### 📝 상황

* Java 코드가 컴파일되고 JVM에서 실행되는 전체 과정을 학습했다.
* Spring Boot의 JAR 실행 구조와 내장 Tomcat의 역할을 정리했다.
* JAR와 WAR, 바이트코드와 머신코드의 차이를 비교하며 이해했다.

### 🚀 액션

* 헷갈리는 개념을 단순히 넘어가지 않고 실행 순서를 직접 설명하며 확인했다.
* 각각의 용어를 따로 암기하기보다 전체 흐름 안에서 연결해 이해하려고 했다.

### 👏 칭찬

* Java와 Spring Boot가 실제로 어떻게 실행되는지 원리 중심으로 접근했다.
* 이해가 애매한 부분을 반복해서 질문하며 개념을 정확하게 잡았다.

## 🔧 개선점

### ❗ 문제

* 바이트코드, 바이너리 코드, 머신코드의 개념이 중간에 섞였다.
* Spring Boot와 Tomcat의 실행 순서를 처음에는 다소 모호하게 이해했다.

### 🔍 원인

* 각각의 개념을 개별적으로 보면서 전체 실행 흐름과의 관계를 놓쳤다.
* JVM, 운영체제, CPU의 역할을 명확히 구분하지 못했다.

### 🎯 액션 플랜

* `.java → .class → JVM → 머신코드 → CPU` 흐름을 다시 정리한다.
* `main()` 실행부터 Spring Context 초기화, 내장 Tomcat 시작까지의 순서를 복습한다.
* JAR와 WAR의 차이를 배포 방식과 실행 주체를 기준으로 비교한다.

## 📚 배운 점

### 💡 배움

* `.class` 파일은 JVM이 이해하는 바이트코드이며 CPU가 직접 실행하는 머신코드는 아니다.
* JVM은 바이트코드를 해석하거나 JIT 컴파일을 통해 머신코드로 변환한다.
* Spring Boot JAR는 `main()`을 시작점으로 스프링을 초기화하고 내장 Tomcat을 실행한다.
* WAR는 외부 WAS에 배포하는 방식이고, 실행 가능한 JAR는 내장 WAS를 포함해 독립적으로 실행할 수 있다.
* Manifest는 JAR 실행에 필요한 메인 클래스 등의 정보를 담는 파일이다.

### 🌱 의미

* Java와 Spring Boot의 실행 구조를 이해하면서 앞으로 JVM, 클래스 로딩, 메모리 구조, 배포 방식을 학습할 기반을 만들었다.
