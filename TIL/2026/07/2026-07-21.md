## ✅ 잘한 점

### 📝 상황
- TIL을 매일 작성하기 편한 환경을 만들기 위해 VS Code의 Markdown Snippet 기능을 적용했다.

### 🚀 액션
- `markdown.json`에 TIL 템플릿을 Snippet으로 등록했다.
- `til` 입력만으로 회고 템플릿을 삽입할 수 있도록 설정했다.
- 템플릿 구조를 여러 번 수정하며 가장 작성하기 편한 형태를 고민했다.
- 원래 참고했던 TIL 글의 구조(상황 → 액션 → 칭찬, 문제 → 원인 → 액션 플랜, 배움 → 의미)를 유지하기로 결정했다.

### 👏 칭찬
- 단순히 템플릿을 만드는 데 그치지 않고, 장기적으로 매일 사용할 수 있는 구조인지까지 고민한 점이 좋았다.
- 불필요한 `templates` 디렉터리를 제거하는 방향까지 검토하며 저장소 구조를 단순하게 만든 점도 만족스럽다.

## 🔧 개선점

### ❗ 문제
- VS Code Snippet이 `til` 입력만으로 자동으로 확장될 것이라고 오해해 설정 과정에서 혼란이 있었다.

### 🔍 원인
- Snippet의 동작 방식과 자동완성, Tab Completion의 차이를 정확하게 이해하지 못했다.

### 🎯 액션 플랜
- VS Code의 Snippet과 자동완성 기능의 차이를 정리해두고, 앞으로 새로운 개발 도구를 사용할 때도 먼저 동작 방식을 확인한 후 적용한다.

## 📚 배운 점

### 💡 배움
- VS Code의 Markdown Snippet을 이용하면 반복적으로 사용하는 Markdown 템플릿을 매우 쉽게 삽입할 수 있다.
- Snippet은 자동으로 문서를 생성하는 기능이 아니라, 사용자가 원하는 시점에 템플릿을 빠르게 삽입하기 위한 기능이다.
- 매일 사용하는 작업은 작은 자동화만으로도 반복 작업을 크게 줄일 수 있다.

### 🌱 의미
- 앞으로 TIL 작성에 드는 시간이 줄어들어 기록 자체에 더 집중할 수 있게 되었다.
- 개발에서도 반복되는 작업은 자동화를 먼저 고민하는 습관이 생산성을 높인다는 점을 다시 느꼈다.
