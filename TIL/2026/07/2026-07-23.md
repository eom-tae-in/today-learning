## ✅ 잘한 점

### 📝 상황
- TCP 연결의 생성부터 종료까지의 전체 흐름을 이해하기 위해 `accept()`, Backlog Queue, `TIME_WAIT`, `shutdownOutput()` 등을 집중적으로 학습했다.

### 🚀 액션
- `accept()`가 어떤 연결을 반환하는지, `TIME_WAIT`에서 OS와 소켓의 역할이 어떻게 나뉘는지, Half-close가 TCP에서 어떻게 동작하는지 흐름을 따라가며 하나씩 정리했다.
- TCP 계층과 애플리케이션 계층의 역할을 구분하며, 현업에서 대부분 애플리케이션 로직으로 송신을 제어하는 이유까지 이해했다.

### 👏 칭찬
- 단순히 동작을 암기하지 않고 **"왜 이렇게 동작하는가?"**를 계속 질문하며 이해하려고 한 점이 좋았다.
- 각각의 개념을 따로 외우지 않고 하나의 연결 생명주기로 연결해서 이해한 점이 인상적이었다.

## 🔧 개선점

### ❗ 문제
- `accept()`가 기존에 통신했던 연결도 반환할 수 있다고 생각했다.
- `TIME_WAIT` 상태에서는 해당 포트를 절대 재사용할 수 없다고 이해했다.

### 🔍 원인
- TCP 연결의 생성과 데이터 송수신을 하나의 개념으로 생각했고, `TIME_WAIT`의 목적을 정확히 이해하지 못했다.

### 🎯 액션 플랜
- TCP 연결의 생명주기를 **3-way Handshake → Backlog Queue → accept() → 데이터 송수신 → Half-close → 4-way Handshake → TIME_WAIT** 순서로 다시 복습하며 각 단계의 역할을 정리한다.

## 📚 배운 점

### 💡 배움
- `accept()`는 이미 통신 중인 연결이 아니라 **3-way Handshake를 완료하고 Backlog Queue에서 대기 중인 새로운 연결만 반환**한다.
- Backlog Queue에는 **아직 `accept()`되지 않은 연결만 저장**된다.
- `TIME_WAIT`에서는 소켓이 이미 종료되며, 이후 들어오는 패킷은 애플리케이션이 아닌 **OS TCP 스택이 처리**한다.
- `TIME_WAIT`는 포트를 무조건 막는 것이 아니라 **동일한 4-Tuple(IP, Port, IP, Port)의 즉시 재사용을 방지**하기 위한 상태이다.
- `shutdownOutput()`은 FIN을 전송하여 **TCP 레벨에서 송신 종료를 상대에게 명확히 알리는 Half-close**를 수행한다.
- TCP는 항상 양방향(Full-Duplex) 통신이며, 현업에서는 대부분 `shutdownOutput()`보다 **애플리케이션 로직으로 더 이상 데이터를 보내지 않는 방식**을 사용한다.
- `write()`의 성공은 데이터를 TCP 송신 버퍼에 넘겼다는 의미일 뿐이며, 상대 프로그램의 처리 완료는 **HTTP 응답과 같은 애플리케이션 프로토콜**을 통해 확인해야 한다.

### 🌱 의미
- TCP를 단순한 송수신 기술이 아니라 **연결의 생성부터 종료까지 OS와 애플리케이션이 각자의 역할을 나누어 처리하는 구조**로 이해하게 되었다.
- 앞으로 소켓 프로그래밍을 구현하거나 네트워크 문제를 분석할 때도, 각 계층의 역할을 구분하며 더 정확하게 원인을 파악할 수 있는 기반을 마련했다.
