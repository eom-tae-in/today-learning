## 📌 오늘 학습 계획

1. **게시글·댓글 코드와 전날 학습 내용 복습**
    - 기존 코드에서 조회 SQL, MyBatis 매핑, DTO, JSON 응답, React 화면으로 이어지는 흐름을 다시 따라간다.
    - 댓글 유무에 따른 관계 매핑과 DTO 생성·변환 구성을 확인한다.
    - Service 호출 경로와 트랜잭션 범위를 되짚어, 이어서 학습할 프록시 기반 AOP와 연결한다.
2. **Spring AOP와 프록시 적용 방식**
    - 비즈니스 로직과 공통 처리를 구분하고, AOP에서 어떤 메서드에 어떤 처리를 언제 적용하는지 확인한다.
    - Aspect·Pointcut·Advice의 역할을 수업에서 다루는 코드의 적용 대상·실행 시점과 연결한다.
    - 외부에서 프록시를 거치는 호출과 같은 객체 내부 호출을 비교하고, `@Transactional`의 적용 방식과 연결해 설명한다.
3. **Filter·Interceptor의 처리 위치와 실행 흐름**
    - Filter·DispatcherServlet·Interceptor·Controller의 연결 관계를 확인하고, Filter와 Interceptor의 적용 경로를 비교한다.
    - Filter의 `doFilter`와 Interceptor의 `preHandle`·`postHandle`·`afterCompletion`이 언제 실행되는지 확인한다.
    - 요청을 다음 단계로 전달하거나 중단하는 조건을 살펴보고, AOP의 메서드 호출 개입과 어떤 차이가 있는지 정리한다.
4. **React와 Spring Boot 게시글·댓글 기능 연동**
    - 기존 React API 호출의 URL·메서드·전달 데이터를 Controller의 요청 처리 방식과 DTO 구조에 대조한다.
    - 댓글 등록 요청을 보내고, Network에서 사전 요청 유무와 실제 응답의 상태·헤더·본문을 확인하며 CORS 설정과 대조한다.
    - 응답 데이터가 React 상태 변경과 댓글 목록 갱신으로 이어지는지 확인하고, 재조회 결과와 화면 내용을 비교한다.
    - 연동 문제가 발생하면 요청 전달, 서버 처리, 응답 변환, 화면 갱신 중 실패한 단계를 찾고 DB 저장 여부도 별도로 확인한다.
5. **전체 흐름 확인 및 TIL 정리**
    - 게시글·댓글 요청 흐름에 Filter·Interceptor·AOP의 적용 지점을 함께 표시해 각 처리의 역할을 정리한다.
    - 복습한 내용과 새로 확인한 동작을 구분하고, 실제 실행 결과·해결한 문제·남은 질문을 TIL에 기록한다.

## 🤔 예상되는 어려움

- **관계 매핑·DTO 변환:** SQL 조회 결과를 객체로 매핑하는 단계와 요청·응답의 JSON 변환 단계를 혼동해, 문제가 생긴 위치를 잘못 판단할 수 있다.
- **AOP·트랜잭션:** 애너테이션이 있다는 이유만으로 부가 기능이 적용된다고 판단하거나, 내부 호출에서도 기존 트랜잭션 안에서 작업이 실행되는 경우를 놓칠 수 있다.
- **Filter·Interceptor:** 둘 다 요청 전후 처리에 관여해 적용 범위를 혼동하거나, 각 후처리 시점을 JSON 응답 처리 완료와 동일하게 생각할 수 있다.
- **프론트 연동:** 브라우저 오류나 화면 갱신 실패를 DB 저장 실패로 해석해, 서버 처리 결과와 클라이언트 처리 결과를 구분하기 어려울 수 있다.
