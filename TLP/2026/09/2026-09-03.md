## 📌 오늘 학습 계획

1. **게시글·댓글 구조와 MyBatis 1:N 관계 매핑**
    - 강의 코드에서 게시글과 댓글의 관계, Mapper의 조회 SQL, DTO 구조를 함께 확인한다.
    - 조회 결과의 여러 행이 게시글과 댓글 목록으로 매핑되는 과정을 추적하고, 실제 조회 결과와 대조한다.
2. **프록시 기반 트랜잭션과 논리적 작업 단위**
    - 게시글·댓글 처리 코드에서 하나로 묶어야 하는 작업 범위와 `@Transactional` 적용 위치를 확인한다.
    - 호출이 프록시를 거치는 경로를 추적하고, 작업 성공·예외 발생 시 커밋과 롤백이 결정되는 조건을 살펴본다.
3. **Builder·생성자 애너테이션과 DTO 변환**
    - `@Builder`, `@NoArgsConstructor`, `@AllArgsConstructor`가 각각 제공하는 객체 생성 방식을 강의 코드에서 비교한다.
    - 요청 JSON을 DTO로 변환하는 역직렬화와 응답 DTO를 JSON으로 변환하는 직렬화를 구분한다.
    - DTO의 생성자·접근자 구성을 확인하고, 변환 오류가 발생하면 어느 방향에서 어떤 설정이 문제가 되는지 점검한다.
4. **WebConfig를 통한 CORS 설정 확인**
    - React의 실제 요청을 기준으로 적용 경로, 허용 Origin, 메서드, 요청 헤더를 WebConfig 설정과 대조한다.
    - 브라우저 Network에서 사전 요청과 실제 요청의 응답을 확인하며 CORS 설정의 적용 여부를 점검한다.
5. **React 게시글·댓글 기능 연동**
    - 강의 코드의 `blog`·`comment` API 호출을 따라 요청 URL, 전달 데이터, 응답 JSON 구조를 확인한다.
    - 응답 데이터가 React에서 어떤 속성으로 읽히고 상태 변경과 화면 갱신으로 이어지는지 추적한다.
    - 백엔드 조회 결과, API 응답, 화면에 표시된 내용이 일치하는지 확인한다.
6. **강의 코드 확인 및 TIL 정리**
    - 관계 매핑, 트랜잭션 처리, DTO 변환, React 화면 갱신을 하나의 요청·응답 흐름으로 정리한다.
    - 실제 확인한 동작과 발생한 문제, 해결 여부, 남은 질문을 구분해 오늘의 TIL에 기록한다.

## 🔄 복습할 부분

- 게시글·댓글의 같은 API를 Swagger UI와 React에서 호출하고 요청 URL·Origin·헤더를 비교한다. Swagger에서 성공한 것만으로 프론트 연동 성공을 판단할 수 없는 이유를 다시 설명한다.
- 실제 React 요청에 사전 요청이 필요한지 확인한다. Network에서 OPTIONS 실패로 실제 요청이 전송되지 않은 경우와 실제 요청은 전송됐지만 응답 접근이 제한된 경우를 구분한다.
- Controller의 응답 DTO, JSON 본문, React의 데이터 접근 코드와 화면 갱신을 순서대로 대조한다. 응답 형식 불일치와 CORS 문제를 각각 어떤 근거로 구별할지 확인한다.
- WebConfig의 적용 경로·허용 Origin·메서드·요청 헤더를 실제 요청과 비교한다. 설정 변경 후 응답 헤더와 화면 결과를 확인해 개선 여부를 판단한다.
