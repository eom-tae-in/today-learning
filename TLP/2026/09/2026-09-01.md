# 🌅 Today Learning Plan

- Controller에서 Service와 Mapper를 거쳐 MyBatis로 데이터에 접근하는 흐름을 설명한다.

---

## 📌 오늘 학습 계획

1. **Controller의 역할과 요청 경로 설정**
    - `@RestController`와 `@RequestMapping`의 역할을 확인한다.
    - Controller가 HTTP 요청을 받아 처리할 메서드로 연결하는 흐름을 파악한다.
2. **Controller에서 요청값을 받는 방법**
    - `@RequestParam`, `@PathVariable`, DTO를 사용하는 경우를 구분한다.
    - 요청값의 위치와 형태에 따라 적절한 파라미터 수신 방식을 적용한다.
    - 전달된 요청값이 Controller의 메서드 파라미터와 DTO에 매핑되는 과정을 확인한다.
3. **Swagger 기반 API 문서 명세화**
    - Swagger를 통해 Controller의 API 정보를 문서화하는 흐름을 확인한다.
    - `@Tag`와 `@Operation`으로 API 그룹과 기능을 명세한다.
    - `@Parameter`와 `@ApiResponse`로 요청 파라미터와 응답 정보를 작성한다.
    - 작성한 명세가 Swagger 문서에 어떻게 표시되는지 확인한다.
4. **Service와 Mapper를 통한 데이터 처리 흐름**
    - Controller, Service, Mapper가 각각 담당하는 역할을 구분한다.
    - Controller에서 전달받은 요청이 Service를 거쳐 Mapper로 이어지는 흐름을 따라간다.
    - MyBatis가 Mapper와 데이터베이스 작업을 연결하는 방식을 확인한다.
5. **MyBatis 설정 확인**
    - `mybatis-config.xml`이 MyBatis의 동작을 설정하는 파일임을 확인한다.
    - 수업에서 다룬 설정 항목이 Mapper와 SQL 실행에 어떻게 반영되는지 살펴본다.
    - Controller부터 MyBatis까지 이어지는 전체 요청 처리 흐름을 정리한다.
