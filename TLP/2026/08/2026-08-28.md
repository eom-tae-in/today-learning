## 📌 오늘 학습 계획

1. **테이블 제약조건 정리**
    - `PRIMARY KEY`, `FOREIGN KEY`, `NOT NULL`, `UNIQUE`, `CHECK`의 역할을 구분한다.
    - 컬럼 수준과 테이블 수준에서 제약조건을 선언하는 방법을 확인한다.
    - 제약조건을 위반하는 데이터를 입력해 DB가 이를 차단하는지 확인한다.
2. **CASCADE와 RESTRICT 비교**
    - 부모·자식 테이블을 구성하고 외래 키의 참조 방향을 확인한다.
    - `ON DELETE CASCADE`를 적용해 부모 삭제가 자식 데이터에 미치는 영향을 확인한다.
    - `ON DELETE RESTRICT`를 적용해 자식 데이터가 있을 때 부모 삭제가 제한되는지 확인한다.
3. **DEFAULT와 날짜 기본값 확인**
    - 컬럼을 생략한 `INSERT`에서 `DEFAULT`가 적용되는 과정을 확인한다.
    - 생성 시각처럼 매번 달라져야 하는 값과 업무상 고정되어야 하는 날짜를 구분한다.
    - `SYSDATE` 또는 `CURRENT_TIMESTAMP`를 사용할 때 DBMS와 컬럼의 목적을 함께 고려한다.
4. **ALTER TABLE과 DML 실습**
    - `ALTER TABLE`로 컬럼과 제약조건을 추가·변경하는 문법을 연습한다.
    - `INSERT`, `SELECT`, `UPDATE`, `DELETE`를 실행해 데이터를 추가·조회·수정·삭제한다.
    - 각 SQL의 실행 전후 데이터를 조회해 실제 변경 결과를 확인한다.
5. **AUTO_INCREMENT와 SEQUENCE 비교**
    - `PRIMARY KEY`가 행을 식별하는 제약조건이라는 점을 확인한다.
    - `AUTO_INCREMENT`와 `SEQUENCE`가 번호를 생성하는 방식이라는 점을 구분한다.
    - 자동 생성된 번호가 항상 연속적으로 유지되는 것은 아니라는 점을 확인한다.
6. **DB 캐시 동작 파악**
    - DB가 데이터와 인덱스 페이지를 메모리에 보관하는 기본 흐름을 확인한다.
    - 동일한 조회를 반복해 최초 조회와 후속 조회의 차이를 관찰한다.
    - DB 내부 캐시와 Redis 같은 애플리케이션 캐시의 역할을 구분한다.

- `ANY`, `ALL` 연산자를 최솟값·최댓값 조건으로 변환할 때 비교 방향을 반대로 판단할 수 있다.
- `NOT IN` 서브쿼리의 `NULL`이 전체 조건을 `UNKNOWN`으로 만드는 과정을 혼동할 수 있다.
- 세 가지 순위 함수의 동점 처리 방식과 그룹별 Top-N 조건을 혼동할 수 있다.
- 작성한 조인 순서와 DB가 선택한 Driving Table·Driven Table이 다를 수 있다.
- `CASCADE`와 `RESTRICT`가 부모와 자식 중 어느 데이터에 영향을 주는지 혼동할 수 있다.
- 현재 날짜를 사용한 기본값이 필요한 경우와 고정값이 필요한 경우를 구분하기 어려울 수 있다.

- 동일한 조회가 빨라지는 현상을 DB 내부 캐시와 완성된 쿼리 결과 캐시로 혼동할 수 있다.

- 제약조건과 번호 생성 방식을 역할, 테이블 종속 여부, 중복 방지 여부로 나누어 정리한다.
