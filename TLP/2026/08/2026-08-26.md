## 📌 오늘 학습 계획

1. **집계 함수와 GROUP BY 기본 구조 파악**
    - `COUNT`, `SUM`, `AVG`, `MAX`, `MIN`의 역할과 `NULL` 처리 방식을 확인한다.
    - 같은 값을 가진 행이 `GROUP BY`를 통해 어떻게 하나의 그룹으로 묶이는지 확인한다.
    - 단일 컬럼과 여러 컬럼을 기준으로 그룹화하는 쿼리를 작성한다.
    - `COUNT(*)`와 `COUNT(컬럼)`의 결과 차이를 예제 데이터로 비교한다.
2. **WHERE와 HAVING의 적용 시점 구분**
    - `WHERE`는 그룹화 전 개별 행을 필터링하고, `HAVING`은 그룹화 후 집계 결과를 필터링한다는 차이를 확인한다.
    - 개별 행 조건과 집계 조건을 함께 사용하는 쿼리를 작성한다.
    - `FROM`, `JOIN`, `WHERE`, `GROUP BY`, `HAVING`, `SELECT`, `ORDER BY`의 논리적 실행 순서를 정리한다.
3. **JOIN의 연결 원리 확인**
    - 기본 키와 외래 키를 기준으로 서로 다른 테이블의 행이 연결되는 과정을 확인한다.
    - 테이블 별칭과 `ON` 조건을 사용하여 명시적인 JOIN 쿼리를 작성한다.
    - JOIN 조건을 누락했을 때 카테시안 곱으로 행이 증가하는 이유를 확인한다.
4. **INNER JOIN과 OUTER JOIN 비교**
    - `INNER JOIN`으로 양쪽 테이블에 연결 대상이 존재하는 행만 조회한다.
    - `LEFT JOIN`과 `RIGHT JOIN`으로 한쪽 테이블의 모든 행을 유지하는 결과를 확인한다.
    - 연결 대상이 없는 행에서 상대 테이블의 컬럼이 `NULL`로 표시되는 것을 확인한다.
    - MySQL과 MariaDB에서 `FULL OUTER JOIN`을 직접 지원하지 않는 점과 대체 방법을 확인한다.
5. **OUTER JOIN의 조건 위치 확인**
    - `LEFT JOIN`에서 오른쪽 테이블의 조건을 `ON`에 작성했을 때와 `WHERE`에 작성했을 때의 결과를 비교한다.
    - 모든 기준 데이터를 유지해야 하는 경우 조건을 어디에 작성해야 하는지 구분한다.
    - 연결되지 않은 데이터를 `IS NULL` 조건으로 찾는 쿼리를 작성한다.
6. **JOIN과 GROUP BY 종합 적용**
    - 부서별 직원 수와 평균 급여를 조회하는 집계 쿼리를 작성한다.
    - 직원이 없는 부서까지 포함하도록 `LEFT JOIN`과 `COUNT(상대 테이블 PK)`를 함께 사용한다.
    - 직원과 프로젝트의 다대다 관계를 여러 테이블 JOIN으로 연결한다.
    - JOIN으로 원래 데이터가 반복되면서 집계값이 증가할 수 있는 상황을 확인한다.
    - 최종 결과의 한 행이 무엇을 의미하는지 먼저 정하고 집계 단위를 맞추는 순서로 쿼리를 검토한다.

## 🤔 예상되는 어려움

- `WHERE`와 `HAVING`이 모두 조건을 지정하기 때문에 어느 위치에 조건을 작성해야 하는지 혼동할 수 있다.
- `INNER JOIN`과 `OUTER JOIN`에서 연결되지 않은 행이 어떤 기준으로 제외되거나 유지되는지 혼동할 수 있다.
- `LEFT JOIN`의 오른쪽 테이블 조건을 `WHERE`에 작성하여 의도와 다르게 기준 행이 제거될 수 있다.
- 직원이 없는 부서를 집계할 때 `COUNT(*)`를 사용하면 직원 수가 0명이 아니라 1명으로 계산될 수 있다.
- 일대다 또는 다대다 관계를 JOIN한 뒤 같은 값이 여러 행에 반복되어 집계 결과가 부풀 수 있다.

## 💡 해결 전략

- 같은 요구사항을 `WHERE`와 `HAVING`으로 각각 작성해 보고 SQL의 논리적 실행 순서에 따라 결과 차이를 확인한다.
- 동일한 예제 데이터를 `INNER JOIN`과 `LEFT JOIN`으로 각각 조회하여 누락되거나 유지되는 행을 대조한다.
- 오른쪽 테이블의 조건을 `ON`과 `WHERE`에 각각 배치한 쿼리를 실행하고 연결되지 않은 행의 유지 여부를 비교한다.
- 직원이 없는 부서에서 `COUNT(*)`와 `COUNT(employee.emp_id)`의 결과를 직접 비교한다.
- JOIN 전후의 행 수와 결과 한 행의 의미를 확인하고, 필요한 경우 각 테이블을 먼저 집계한 뒤 연결한다.
